# E3 live evaluation

Protocol, limits and preregistered decision rule: [plans/E3.md](plans/E3.md).
The runner is an explicit trusted evaluator, not a new product CLI or general sandbox.
It requires Linux, Docker, built SDK packages and a working AgentRig subscription login.
It does not inherit project configuration, API keys, backend URLs or model overrides.

Build the two images from `eval/` (not the repository root):

```sh
pnpm build
docker build --target worker -t agentrig-e3-worker -f eval/Dockerfile eval
docker build --target checker -t agentrig-e3-checker -f eval/Dockerfile eval
docker image inspect agentrig-e3-worker agentrig-e3-checker --format '{{.Id}}'
```

Record the returned immutable image IDs in an external settings JSON:

```json
{
  "worker": "sha256:REPLACE_WITH_WORKER_IMAGE_ID",
  "checker": "sha256:REPLACE_WITH_CHECKER_IMAGE_ID",
  "source": "/absolute/pinned-is-number-source",
  "output": "/absolute/new-evidence-directory"
}
```

Commit the evaluator before running `node eval/live.mjs /absolute/settings.json`. The output
directory must be outside the evaluator checkout and must not exist. Failures preserve artifacts; the runner never resumes/overwrites an
attempt or silently retries a task. Preparation may use network on pristine pinned inputs;
model tool calls and checks have no network. No host credential/evaluator/sibling-run mount is
exposed to the model. Checker code exists only in the separate checker image, used after the
model session. Docker container cleanup targets only UUID names generated by that call and
does not delete workspace/evidence files, user containers, images or volumes.

The resulting protocol records every planned slot. Each completed attempt has main session
JSONL, independent checks and their process output, E2 report, exact provider-call usage journal,
observer receipts, task artifacts/diff and timing. Training and ingest are separate, followed by
a hashed frozen corpus. USD rates are deliberately absent: token consumption is not an API bill.
Cancelled/incomplete provider calls remain unknown. Three incomplete calls stop scheduling;
each carries a conservative scheduling reserve, not invented consumption. Provider errors other
than cancellation/timeout stop immediately. Local token
guards can overshoot by in-flight responses; they are not subscription quota enforcement.

The shell-only task surface is fixed across all conditions, with a fresh shell per call and
file-change observations for detectors. It is not a comparison of richer built-in file tools,
online memory learning, dream, subagents, or model families. No compaction is enabled; bounded
contexts/run budgets are part of this experiment. Graders see the task and a bounded diff, not
independent expected answers, and cannot override the outcome checks.

A4/X4 need genuine human prose review under EVALSET's frozen rubric. Their automatic BLOCKED
results must remain unchanged. Provide the human an answer packet, then attach separately
attributed verdicts through E2's humanVerdict field. Pending or failed checks never become PASS
because the maintainer or a model reviewer thinks an answer looks right.

## Publication

After collection has closed, `node eval/pack-live.mjs CLOSED_EVIDENCE_ROOT NEW_PUBLICATION_DIRECTORY`
creates a hashed, compressed evidence bundle, an index, a summary with unrun/blocked slots and
an untrusted-answer packet for human review. It never changes verdicts or copies task workspaces,
dependencies, credentials, or mutable session snapshots. It preserves created partial attempts
as well as completed ones. It refuses an existing publication directory.

The gzip payload is JSON with `files[path] = {sha256, bytes, base64}`. Inspect a selected record
without extracting or executing anything:

```sh
node --input-type=module -e 'import{readFileSync}from"node:fs";import{gunzipSync}from"node:zlib";const b=JSON.parse(gunzipSync(readFileSync(process.argv[1])));console.log(Buffer.from(b.files[process.argv[2]].base64,"base64").toString())' evidence.json.gz 001-A1-s0m0-r1/report.json
```

Read [collection notes](E3-COLLECTION-NOTES.md) with results. Limitations discovered during
collection are disclosed there, not hidden by changing the preregistration or silently rerunning.
