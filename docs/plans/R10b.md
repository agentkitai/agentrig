## Contract

Trusted SDK `parallel({ maxConcurrency: 4 })` selects bounded scheduling; the integer
range is 1–16. Sequential remains default, regardless of provider parallel-tool support.
No model/config code loading or CLI strategy option. The runtime bridge is an internal
WeakMap on the actual strategy context: copying a context without its binding falls back
to sequential rather than guessing hazards from model input. Custom strategies remain
trusted host code, not an isolation boundary.

A FIFO preparation gate runs the existing schema/hook pipeline and computes permission,
operation, declared paths and effects from final revalidated input. Metadata callbacks
are not duplicated to predict hazards. Trusted registered extension declarations use the
same cooperative basis as SDK declarations, not a sandbox. Permission evaluation, grant audit/counting and
ordinary approval complete in that gate. All approval callbacks, including late separate
sandbox-escape consent, additionally share one prompt mutex. A held hazard lease covers
execution, result/provenance/post-hook processing, checkpoint cleanup and failure flush.
Denied/invalid calls release the preparation gate without running a body.

Only explicit trusted `read-only` + `read`, or `workspace` + `write`, with 1–64 declared
paths (each nonempty, at most 4096 characters, no NUL) are parallel candidates. Builtin
write_file/edit_file explicitly declare workspace effects; permission names alone never
establish effects. Canonical real paths, ancestor/descendant relationships and existing
device/inode hardlink identities determine conflicts. Path keys conservatively normalize
NFC and lowercase even on case-sensitive filesystems (extra serialization is acceptable).
Missing targets may run concurrently only for ASCII letters/digits, spaces, dots,
underscores and hyphens (with no trailing dot/space or reserved device spelling) under a resolved
immediate parent. Trailing dot/space, non-ASCII names, stream/Windows-special syntax and
reserved device spellings are exclusive on every platform; lowercase is not universal
Windows name attestation. Directory targets are exclusive because traversal can follow
child aliases outside the tree; no unbounded recursive inventory is attempted. Dangling
symlinks, missing parents, failed resolution, unidentifiable inode or special files are
exclusive. Canonical classification is refreshed after waiting for prior work. Concurrent
reads may overlap; any overlapping writer serializes. A queued conflict or exclusive call
is an ordered barrier: later independent work cannot pass it.

Unknown effects, empty/unbounded/unresolved paths, exec/net/network/background operations
are exclusive. Any configured hooks/checkpointers or currently reported background work
force sequential pipeline execution, because these callbacks/writers can affect undeclared
state. This fallback is deliberate, not a claim that every independent tool is supported.
Declared effects/paths are trusted cooperative contracts, not attestation of arbitrary
JavaScript, command behavior or external filesystem mutation. Permissions, MCP definition
consent, fresh external-input approval and sandbox policy retain their independent gates.

Results return in model-call order; events append through the existing single ordered
chain in actual emission order, with contiguous seq and unchanged call/result correlation.
The pool stops taking queued work on cancellation or fatal pipeline rejection and joins
all started pipeline promises before returning/throwing. Parallel cancellation discards
the batch from conversation append. Sequential's historical final-call abort asymmetry
and all pinned traces remain unchanged. Existing raceAbort/orphan reporting still applies:
joining a pipeline is not a claim that uncooperative host/remote effects have stopped.
No new timeout abandons destructive I/O, and no live provider/evaluation spend is used.
A fatal sibling can therefore wait for an already-active human prompt to be answered.
Queued callbacks are checked for stopped state before invocation: an aborted/failed batch
does not later surface a fresh queued prompt when the mutex becomes available.
