# R13d — runtime context principals and instruction delegation

Source trust (`user/project/external/tool-output/generated`) is not instruction authority.
This row adds optional recursive context principal/authority metadata and assigns it at actual
runtime assembly boundaries. It does not implement R13c permission restrictions or change R12a
tool-dispatch grants. Host JavaScript and trusted SDK configuration are not sandboxed.

New user input is user/instruction; host system instructions are platform/instruction. Runtime
replan/interrupted-turn reminders are platform/advisory (embedded supervisor/model text must not
borrow platform instruction authority); supervisor
and hook inputs are advisory by default. Hook identity is captured from registered objects,
collision-safe even for missing or duplicate display ids. Only an unambiguous explicit registered
id can receive instruction delegation. Hook returned fields, model prose, vendor JSON and copied
tokens cannot select an identity or grant authority.

All accepted hook mutation surfaces retain attribution: user_prompt injection/replacement,
pre_model's existing narrow `{system:string}` replacement/appending, post_model injection,
pre_tool input changes and post_tool display changes. Existing functional behavior remains;
the system bill of materials and unified request carry runtime context metadata for actual
changed segments. No unsupported vendor fields are added, and metadata cannot guarantee model
obedience. Tool input changes still pass existing schema and permission checks.

Trusted host config/control can explicitly delegate and revoke instruction authority to named
hooks. A bounded per-run live receipt set and visible audit events govern this separate seam.
Revocation downgrades retained delegated content on the next request; original immutable events
remain honest history. Resume starts with no prior live receipt, and a new delegation never
revives an old token. Delegation changes do not grant tool permissions.

SDK usage: `AgentConfig.hookInstructionDelegations: ["registered-id"]` opts a unique named hook
in for each run; `session.control.setHookDelegation?.("registered-id", false)` revokes it.
The control returns false for closed sessions, ambiguous/missing/reserved ids or an exhausted
grant budget. At most 128 grants and their matching revocations produce 256 audit records per
run; exhaustion never blocks revocation. `context.delegation` events expose the principal, action
and receipt. Receipt text alone is non-authoritative without the current live registry.

`ContentBlock.context` is recursive and optional; `ModelRequest.systemContexts` aligns with the
nonempty system components joined by blank lines. Existing trusted host `PromptBlock.authority`
remains respected; actual hook changes receive only their registered authority. Mixed hook
contributions and synthesized summaries are platform/advisory. Unified metadata is omitted from
vendor wire requests and the local token estimate; it is not a vendor-enforced instruction role.

Compaction, eviction, provider projection, canonical storage and resume preserve source metadata
or conservatively downgrade new synthesis. A custom transform cannot mint user/platform authority
through returned labels. Legacy missing metadata stays readable and is not retroactively guessed.

Acceptance: actual hook/steer/request/storage traces, duplicate-name isolation, forged metadata,
delegation/revocation/resume behavior, schema/provider and permission non-expansion controls.
Named negative mutations fail and are restored. Exactly one bounded independent review, full
build/typecheck/tests, current-main exact-head three-platform CI and post-merge CI gate delivery.
Optional polish belongs at ROADMAP's end; this is one row, not a new policy framework.
