Builder: **agentrig**, conductor **100108d7**. One implementation child, no nested

continuation does not reset R17b's historical children, usage, halts, three repair

## Fixed contract

> Feel budgets in CI: measured on the fake provider and asserted like the viewport
> height: cold start to prompt under 400 ms, first streamed token within one tick
> of provider first byte, permission prompts per E1 task, turns to done per E1 task,
> TUI frame cost per event. A regression fails the build; the numbers print in
> `agentrig doctor`.
>
> Acceptance: a deliberately slowed startup fixture fails the budget test (mutation).

No acceptance or permission-policy change is proposed. R17d–R17g are not pulled
forward. No model capability, tool authority, permission grants or sandbox policy
is added or widened.

## Measurement and implementation

- `pnpm build` produces the real CLI entry as a minified ESM esbuild bundle. Ink
  and React remain ordinary external dependencies (one reconciler/React instance).
  All tsc module outputs and declarations remain available. The bundle avoids
  hundreds of cold-process module resolutions; it is not a fake startup launcher
  or a pre-rendered prompt. The build uses the same esbuild version already used
  by the workspace's test transformer.
- `pnpm feel:check`, in an idle Linux CI phase after build and before parallel unit
  tests, starts the actual `dist/index.js` in the existing credential-free local
  SSE/PTY fixture. It asserts cold **process** start to visible prompt <400 ms.
  This is a cold process, not a filesystem-cache flush or a percentile claim.
- The acceptance mutation inserts an actual 450 ms delay after the built CLI's
  shebang. The same PTY fixture and same budget assertion must reject it. The
  entry is restored in `finally`, with an exact-byte assertion. No injected fake
  timing result stands in for the startup path.
- A separate isolated fake `ModelProvider` yields the first text byte; a repeating
  `setImmediate` counter measures **event-loop ticks**, not a substituted wall-time
  allowance. The byte traverses the real Agent, SessionStore, controller and
  non-debug App/Ink renderer. Both canonical event delivery and visible streaming
  must occur within one tick. The measured first-byte clock is not submit-to-token.
- The initial core test failed at **10 ticks**. The existing async log append
  introduced multiple I/O turns before a delta could be emitted. Only already-live
  `model.delta` appends now use synchronous append: the small chunk is still
  persisted before publication. Append errors still reject; sequence advances
  only after success. All other events retain asynchronous persistence. This is
  a deliberate latency/brief event-loop-blocking tradeoff, not speculative
  publication before persistence or a new event schema.
- The real renderer receives 16 separate streamed events against 2,000 lines of
  scrollback. Each must yield a measured frame. Process CPU from canonical event
  delivery to its stdout frame is measured per event; the maximum must be <16 ms.
  This is CPU cost, separately recorded from frame wall latency. The 50 ms spacing
  prevents coalescing from making the per-event count vacuous; it is outside each
  first-byte/event-to-frame measurement window.
- All eight original E1 reference traces run, including real read/write tools,
  unchanged `RulePolicy(defaultRules)`/`onAsk`, canonical `turn.start` counts and
  the evaluator's pinned behavior/regression/submitted-test checks. Counts are
  the existing R17a reference ceilings: A1/A2/X1–X4 **2 prompts / 4 turns**, A3
  **3 / 5**, A4 **2 / 5**. These are the original core reference traces, not live
  model capability results or the R17d recommended-profile friction experiment.
  A4/X4 remain evaluator **BLOCKED**, with automatic behavior PASS and manual
  review pending. No human verdict is fabricated.
- Boundary JSON is validated with zod; all eight distinct tasks and all sixteen
  frames are required. Missing, duplicate, negative and non-finite data cannot
  turn the budget green. CI uploads the current-head `feel-results.json` artifact.
- Plain `agentrig doctor` prints the checked-in **measured reference**, its date,
  platform/Node version, actual values and ceilings for all five metrics. It
  explicitly does not call this a measurement of the user's machine or provider.
  This keeps ordinary doctor non-billable and does not run task writes or fixture
  dependency installs in a user's project. `pnpm feel:check --record` refreshes
  the reference only after all actual measurements pass; CI checks fresh values
  without modifying the committed reference.

## Initial real evidence

The first complete fixture run recorded startup **327.549 ms**, rejected the real
startup mutant at **763.168 ms**, and restored the entry bytes. Canonical first
byte: **0 ticks / 0.750 ms**; visible stream: **0 ticks / 2.092 ms**. Sixteen actual
frames: **0.983 ms mean / 2.212 ms maximum CPU**. All eight task sessions ended
`done` with automatic behavior PASS and the prompt/turn counts above. The checked-in
reference carries the task-session ids and measurement metadata; CI publishes its
own fresh report rather than claiming these initial numbers describe every host.
