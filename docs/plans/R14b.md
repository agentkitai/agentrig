# R14b — bounded candidate evidence association

## Contract

R14a declarations now have an evidence side in supervisor state. Only the exact single-line
grammar `<command> exits <nonnegative integer>` is supported (1024-character declaration bound;
exit integer at most nine digits). Command bytes are compared exactly, including quoting and
spacing. This covers test/lint/typecheck commands and `git diff --exit-code`; arbitrary prose,
HTTP assertions and diff meaning remain unsupported/unverified. Check text is never executed.

The built-in foreground shell creates an internal immutable receipt bound to the exact result
and live ToolContext objects. Core consumes it once before output hooks/overflow and stamps an
additive `tool.result.commandOutcome`: actual post-hook command, launch cwd, exit code, timeout
and abort flags. Model text, copied fields/results, a tool named bash, MCP metadata and ordinary
custom results cannot mint receipts. Background starts and legacy/failed-to-return executions
have none. Long command/cwd observations omit the receipt rather than emit unbounded metadata.
SDK JavaScript is trusted code, not a sandbox; canonical logs are trusted local records, not
cryptographic attestations. The receipt observes the shell process, not its descendants or the
semantic quality of the command. A command that merely exits zero can still be a useless check.

`SupervisorState.planEvidence` is a pure replayable per-current-item attempt ledger. A plan must
exist before the matching call. Each attempt begins unknown; only a same-session, same call-seq
and provider-ID result with matching command/cwd and coherent exit/ok can record `exit-match`
or `exit-mismatch`. Interruption, missing outcomes, no completion and disagreement stay unknown.
Raw output snippets are never an exit oracle. Every item remains `verification: unverified`;
these are candidate observations, never semantic acceptance, completion or permission proof.

Attempt arrays are chronological by call sequence. The last entry is the latest attempt,
including pending/unknown and failing observations; consumers must not cherry-pick an earlier
match. At most 100 current items, 16 attempts per item and 400 pending calls are retained.
`omittedItems`, `omittedAttempts` and sticky `incomplete` make pruning visible. Unfinished attempts
become unknown at turn/session boundaries. Duplicate IDs cannot associate; oversized identities
are bounded and unverified. Status-only updates retain history, but changed id/text/check/scope,
removal/re-addition or ambiguous identity cannot inherit old success. Full log replay across resume
retains earlier observed failures; fresh observers of only a tail cannot invent omitted history.

This is a supervisor state view over immutable canonical events, not a rewrite of raw attempt
files. R14c claim/evidence presentation and model grading, R14d independent outcome lanes,
automatic check execution and general semantic matching remain separate. No live evaluation spend.

## Validation and gates

Actual scripted-provider sessions exercise foreground shell execution, output-hook laundering,
pre-tool replacement, repeated IDs, successful then failing final runs, real background starts,
timeout, immutable storage, resume and the actual attached supervisor versus replay. Public schema
and internal identity tests distinguish optional legacy fields, forged/copy receipts and one-use
immutable observations. Bounds/ambiguity/correlation fixtures keep unsupported checks unverified.

R12d main `2df8c25` is integrated with live child grant bindings preserved. Build/typecheck/full
tests, detected/restored negative controls, one bounded independent Claude review and latest-main
exact-head three-platform CI gate delivery. Root merges only after the previous main gate is green.

Initial integrated build/typecheck/full four-worker suite passed 2,377 tests plus two skips across
132 files (33 seconds); 18 focused new cases passed. Removing the canonical receipt and allowing
an earlier passing observation to mask the final failure each failed the named actual attached
runtime test; both mutations were restored. First fresh-worktree typecheck needed package build
artifacts, then passed normally; fixture setup was corrected to honor R13c fresh consent after
advisory output hooks and the actual HookContext.tool.name shape, without weakening assertions.
