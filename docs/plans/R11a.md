# R11a — additive net permission and sandbox composition

`net` is a new, distinct permission class. It defaults to ask (unattended denial), participates
in explicit rules and live scoped/child grant records, and maps to R13c's existing network
expansion category. Legacy `network` stays separate and retains its existing behavior. No
tool-name, model-text or MCP hint inference supplies authority. There is no fetch tool in this
row; R11b owns that implementation.

The runtime checks the selected live sandbox policy before a net tool body or expansion
dispatch bookkeeping, even for trusted tools declaring sandbox compatibility. A non-none
policy without `network: true` refuses execution. CLI `--sandbox-network` and boolean config
`sandboxNetwork` expose that explicit SDK policy. They do not grant net permission; `--allow
net` and YOLO do not enable sandbox network. Mode none has no OS sandbox enforcement.

An independently established policy refusal retains the existing fresh, one-invocation
sandbox-escalation escape. Explicit approval executes outside the sandbox; it does not enable
network inside it. Standing/scoped grants cannot answer that separate consent. Without a
handler it fails closed. Parent sandbox narrowing prevents children enabling forbidden network.

This is trusted-tool composition, not containment of arbitrary host JavaScript. Existing
provider traffic, MCP server processes, and undeclared behavior do not become controlled merely
by adding a class. Destinations and other effects remain unknown; no hostname scope is claimed.
