## Eligibility and configuration

- Strict config `notifications: off|bell|desktop|both`, default **off**.
  `notificationIdleSeconds` is an integer 1–3600, default 30. Explicit operator
  opt-in, no model/event field can enable notifications. CLI negative override
  wins over config. Ordinary headless run/CI, ACP, MCP and scheduler never create
  the notifier, emit BEL or launch a desktop helper.
- Mounted interactive TUI with both stdin and stdout TTY only. Idle means elapsed
  time since observed keyboard input in this TUI, not OS/window focus or global
  user inactivity. No focus tracking, daemon, polling external applications or
  terminal input reinterpretation. This implements the roadmap's idle alternative.
- Permission asks, supervisor escalation and ask_user use actual live controller
  identities, not matching event prose. Notify once per still-pending visible
  prompt after the idle threshold, including a prompt initially arriving while
  the operator was active. Recheck identity and eligibility immediately before
  delivery; answered/cancelled/replaced requests cannot notify later.
- Session completion is observed from the active session's actual ended state,
  once per identity and only if already idle at completion. Never infer completion
  from model text or emit notification events into canonical logs.
- At most four active candidates, one delivery per two seconds, one desktop
  process in flight and one coalesced latest pending delivery. No unbounded queue
  or duplicate notifications on state redraw. Input resets the idle deadline;
  provider progress does not. Teardown cancels timers/subscriptions and joins work.

## Delivery and ownership

- Bell is the literal BEL byte, only through the mounted TTY writer. Desktop
  messages are fixed generic labels for permission/question/supervisor attention
  or session end. No task, path, tool input, model/error prose, session ID, or
  arbitrary configured command enters notification arguments.
- Desktop support uses a fixed executable location: `/usr/bin/osascript` on macOS
  or `/usr/bin/notify-send` on Linux, only if a regular executable is available.
  No shell, repository PATH lookup, package installation or external service.
  Windows and absent backends report bounded unavailability once; bell remains
  available only if the selected mode includes it. Delivery is best-effort, not
  proof the desktop displayed or the human noticed it.
- Root approved a small internal extraction of existing review-process ownership
  into a shared process helper. The public ReviewProcess remains git|gh only,
  with unchanged environment sanitization, 15-second/64-KiB defaults and error
  semantics. Notifications supply fixed backend/environment, 2-second execution
  and 4-KiB combined output bounds; output is discarded. No generic user command
  API or evaluation-support runtime dependency is introduced.
- Cancellation joins the exact owned child/group and kill request, preserving
  Windows's bounded taskkill cleanup. No broad process-name kill, detached-process
  containment claim or abandoned background notification after TUI return.
