# R14c — claims versus observed evidence

## Contract

The existing M6 RubricGrader gains a claims-vs-evidence row and the CLI gains
`sessions show --evidence <id>`. Both use the R14b canonical same-call evidence fold, unchanged
command-exit grammar and bounded candidate observations. No command execution, additional model
call, numeric score, R14d outcome lanes or semantic-proof claim is added.

The report distinguishes current plan status from candidate outcomes. Dropped items are shown as
dropped, not required completion claims. A current declared pending/in-progress item is unfinished
even if its command exit matched. A done declared item with no latest matching candidate is
unverified: missing/unsupported checks, failed or unknown outcomes do not borrow earlier success.
Matching exits never force pass; the model must still assess whether the command meaningfully
checks the requirement. Legacy items without declarations are visibly undeclared/unverified but
introduce no new deterministic completion requirement. Genuine complete legacy/no-declaration
direct grader inputs keep their existing request and verdict behavior. Attached legacy grading
adds an explicit current-run scope note but no new deterministic completion requirement.

Known gaps can only force `pass: false`, retaining concrete bounded reasons even when the model
returns optimistic JSON or malformed output. Report rows/text omissions, pruned evidence and
sequence/prefix discontinuities stay incomplete and force a gap. Removing declarations can change
the current scope; this is not a semantic task-completion oracle or a historical-claims detector.

## Bounds and runtime path

The evidence report retains R14b's 100-item/16-attempt bounds and scans at most 100,000 events.
It renders at most 12,000 characters with whole-row omission counts, and at most 32 detailed
structural gaps plus an omitted-gap count. No raw stdout/stderr, task narration, provider config
or credentials are copied into the report. Declared checks are local user-visible content and may
themselves contain sensitive data; this is not the later redacted-export feature.

The grader bounds additional evidence-bearing trajectory text at 20,000 characters, with a
visible omission marker and deterministic gap; the existing overall auxiliary prompt/time/token
limits, cancellation and accounting still apply. A first large-plan test exposed the existing
condensed-trajectory expansion; this cap closes that path rather than raising limits.

Actual attach keeps the same streaming collector over the current run's full event stream, not
just its 400-event recent trajectory. It anchors only a trusted first session.start/session.resume
boundary, including a legitimate nonzero sequence on resume/fork. Its report explicitly names
the start sequence and says prior history is not assessed. Pre-resume declarations/outcomes are
not loaded or verified by that run's collector; they must be re-declared for current-run grading.
The CLI's full physical-log scope remains separate. No history-seed seam or extra file read is
added. Direct trajectory prefixes without complete physical history remain incomplete.
Attach supplies a fresh frozen report snapshot through optional trusted
`GradeInput.evidence`; strings and the gap array cannot be mutated. This is a host API seam, never
a model-returned report. Direct graders fold their supplied trajectory and detect missing prefixes
or internal sequence gaps instead of assuming omitted history had no declarations. No second
history fetch or raw-log write is added. Reports used only for display are not resume caches.

The CLI streams the named physical canonical log (not fork ancestors), requiring a valid ordered
log ending with `session.end`. It refuses conflicting `--json`, unfinished/corrupt/mixed-identity
logs, over 32 MiB or 100,000 events, and size/mtime changes across reading. It does not load run
config or call a provider. The before/after metadata check is a cooperative snapshot check, not
an adversarial transactional filesystem guarantee; a later explicit resume can append new history.

## Acceptance and gates

Actual scripted-agent foreground runs with identical success narration and identical optimistic
fake grader responses discriminate final exit 0 from final exit 1. A matching exit cannot override
a negative model verdict. A separate actual attach fixture puts the declaration/failure over
400 events behind the grading trigger and still reports the specific deficit. CLI parsing over a
real saved canonical log produces the same report, preserves bytes and requires no network/config.
Legacy/dropped/unfinished/missing checks, omissions, malformed output and ordering have fixtures.

controls, exactly one bounded independent review and updated-main exact-head all-platform CI gate
