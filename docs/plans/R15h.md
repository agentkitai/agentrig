## Contract before implementation

- Only trusted canonical project `.agentrig/agents/<name>.md`; no home, package,
  remote, executable loader or credential configuration. Discovery refuses escaping
  symlinks/junctions and malformed/ambiguous roles before body use. Definitions are
  bounded immutable per-build snapshots; later file edits require another build.
  Hashes identify observed definitions, not authorship or tamper-proof storage.
- At most 32 roles, 64 KiB/file and 1 MiB aggregate; 8 KiB frontmatter and 32 KiB body;
  lowercase filename names at most 64 characters; 64 exact tool names of at most
  128 characters. One strict version-1 R5e-family schema, duplicate keys and unknown
  fields refused. Supported flat scalar syntax plus JSON-array `tools`, not general YAML.
- `tools` is required (empty is valid). `model-role` defaults to `subagents` and names
  only existing `main`, `supervisor`, `memory`, `subagents` routing; it never supplies
  provider credentials/options. `max-turns`, when present, is an integer 1–1000 and
  only lowers the existing inherited child cap.
- `delegable: false` is the default and removes further child spawning. `true` only
  preserves already-allowed `subagent` availability, existing depth/pool limits and
  grant rules; it never makes a non-delegable grant delegable.
- Existing subagent input gains optional `agent`. Unknown/unavailable names refuse,
  including when no valid roles loaded; input must not be silently stripped into a
  generic spawn. `agent` plus explicit `provider` refuses conflicting selection.
  Generic calls without `agent` retain their existing behavior.
- Tool/turn restrictions intersect monotonically with inherited constraints before
  child construction and recursive tool rebuilding. Grandchildren cannot recover
  root capabilities by selecting another role or omitting a role. Tool restrictions
  apply to actual dispatch, including internal diagnostic checkers, not just provider
  advertisement. Blanket policy, standing grants or approval cannot override them.
- R12d views remain live, task-sealed and revocable, intersected with the tool allowlist;
  no copied grants, remapped paths, new authority framework or broader sandbox. A role
  cannot add tools absent from the trusted child configuration. Trusted SDK JavaScript
  remains host code, not a sandboxed principal.
- Body supplies the child role system text with project/advisory provenance. It is not
  a fresh user instruction and cannot clear R13c restrictions. Bounded runtime role
  name/hash/effective-constraint receipts identify actual selection; persisted events
  and resume never recreate permission authority. No body-text authority inference.
- Resuming with the same role-built SDK agent retains its live tool constraints. An
  explicit operator CLI resume constructs a new root agent using current trusted
  configuration; it is not a reconstruction of the old child actor. Historical role
  receipts do not recreate grants or restrictions. Existing conservative resumed
  external ancestry remains until actual fresh human input, not role prose, clears it.
- `read_output` and `core:diagnostics` are not implicit capabilities. A write-only role
  can make an authorized edit while its configured diagnostic checker reports
  unavailable because the internal exec tool is excluded. Filesystem checks bound
  ordinary canonical containment, not hostile concurrent-writer attestation.
