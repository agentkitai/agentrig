## Input and runtime

- `agentrig run --ci` requires exactly one explicit `--task-file <path>` or
  `--event-file <path> --event-field <selector>`. The only selectors are
  `issue.body`, `comment.body`, and `pull_request.body`; no expression evaluation.
  Positional tasks, resume and CI-only flags outside CI mode refuse rather than
  create ambiguous authority. Existing ordinary run behavior stays unchanged.
  Effective JSON/verbose output also refuses before provider work rather than
  silently bypassing or ignoring the bounded report format (root-approved clarification).
- Files must be stable regular non-symlink UTF-8 inputs. Task text is nonblank and
  at most 16 KiB; JSON event input is at most 256 KiB and depth 16. Bounded reads
  and strict selected-value validation precede any provider work. Unselected
  event fields are opaque, never config, environment, repository or argv input.
  No implicit `GITHUB_EVENT_PATH` read, checkout, fetch or payload execution.
- The actual runtime task is empty, with the selected text passed through the
  existing `advisoryContext` seam. A fixed host system instruction explains its
  CI purpose. No nonblank synthetic user prompt or fresh-user reset is minted.
  Payload text cannot grant permission or clear the external-input restriction.
- Reuse `runCommand` / `buildAgent`, with a small trusted observer/ask/advisory
  input seam, not a second agent loop. CI is always headless. Effective YOLO or
  dangerously-skip-permissions refuses before execution; other explicit policy,
  trust, sandbox and provider settings keep their existing meaning.
- Actual unresolved permission asks deny and abort through the live runtime,
  stopping queued effects and forcing nonzero exit even if a later model result
  says done. Explicit denials never become consent. No interactive fallback.
- Fixed CI ceilings are 20 turns, five minutes and 50,000 main-model tokens;
  smaller configured values win and clamping is reported. Existing per-response
  and priced `maxUsd` validation remain. These are the existing runtime's limits,
  not aggregate auxiliary/child or hard remote billing caps. Cooperative abort
  and existing cleanup limitations stay explicit. No provider or live eval spend
  is used to implement or test this row.

## Reporting and optional comment

- Require explicit `--report <path>` and/or the complete
  `--pr <number> --repo <owner/repo> --comment` combination. Payload fields never
  choose output paths or PR targets. These are literal operator-selected outputs.
- File output is create-only under a canonical existing parent: no directory
  creation, symlink target or silent overwrite. The explicit report flag grants
  this bounded host output operation, not model file-writing authority. A report
  is reserved before provider work so occupied/unsafe destinations refuse early.
- Markdown is at most 64 KiB. Fixed fields record outcome, session identity,
  effective limits, permission refusal counts, main usage and honest auxiliary
  coverage. Retain at most 16 KiB of final assistant text, with explicit omission;
  no raw tool outputs, task bodies, provider errors, environment or credential
  bundles. Clone and reuse existing export redaction for report-only content;
  logs are never rewritten. Render model text inertly and escape control content.
  Heuristic redaction can still miss arbitrary secrets; no secret-free guarantee.
- A local report remains available on refusal, runtime failure or cooperative
  cancellation, with partial/unknown status explicit. Output failure is nonzero.
  Comment-only failure still emits a bounded safe diagnostic; no implicit file.
- Reuse R15e fixed-argv owned GitHub process, authorization and identity checks.
  Every `gh` read/post needs configured exec and net permission, including metadata
  reads; asks deny. Host `gh` refuses under an enforcing sandbox, even if a caller
  tried YOLO. Pin repository, PR number and base/head before execution and recheck
  before posting. One explicit comment, no edits/retries or model text as argv.
  No comment after cancellation, invalid outcome or incomplete accounting.
  Remote check-and-post is point-in-time, not transactional or attested identity.
