## Decision

Support **ordinary trusted user-authored SDK composition**, without a packaged
orchestration runtime. Renunciation 8 prohibits adopting an external workflow
engine; it does not prohibit users writing an ordinary host program against the
existing SDK. This closes the decision itself; it creates no further build row.
Review and PR/post-main delivery gates remain pending.

The supported composition boundary is:

1. The operator chooses tasks, finite fan-out/turn/time/token limits, permission
   policy and verification commands. Trusted SDK code may configure existing
   `parallel({ maxConcurrency })` and `subagentTool({ isolation: "worktree", ... })`.
   The strategy enforces concurrency 1–16 (default 4); child-pool and retained-worktree
   limits can be stricter. Concurrency is not a total-session or spend budget.
   These are scheduling/child seams, not a guarantee that a model emits the desired
   plan. Generic child behavior remains available; R15h roles are not required.
2. Children execute through normal runtime dispatch and its final validation,
   permissions, live delegated grant views and sandbox rules. Calling a tool's
   `.execute()` directly is not an equivalent authorization path. A trusted host
   script has ambient host authority; the SDK does not contain arbitrary JavaScript.
3. User-specified checks must inspect actual candidate bytes and return observed
   outcomes, not accept a child's narrative as proof. Prefer independently defined
   task acceptance checks. Verification itself requires authority and finite bounds;
   model-generated tests or successful exit codes alone do not establish task quality.
4. Inspect retained candidates and apply serially through separately authorized
   normal actions. Recheck the current parent baseline and patch applicability
   immediately before each application; a previous ready marker is not standing
   permission or a lock. Check/apply is not atomic against external writers.
   Recheck affected acceptance conditions on the combined parent result before
   treating it as verified. No automatic conflict resolution or GitHub merge follows.
5. Failed, incomplete, aborted, conflicting or stale candidates stop that integration
   path and retain artifacts for operator inspection. Resume is not exactly-once
   replay of external effects. Do not silently retry or clean up retained worktrees.

Default parallelism remains off. R10c's worktrees isolate ordinary relative file
operations, not broad exec/absolute paths or shared Git metadata. Enforcing parent
sandboxes refuse its host Git preparation; no new escape is authorized here.
Existing child pool/retention bounds still apply. R15i's delivered ledger is not a
prerequisite for this decision, and no unattended default, cross-session spend
ceiling, subscription charge or hard remote-billing bound is claimed.

Not added: a product workflow command, executable recipe, YAML/JSON DSL, dynamic
code loader, durable DAG engine, automatic rebase/merge, general retries, distributed
workers, new trust framework or a provider capability inference. A future runnable
example can be optional documentation at ROADMAP END, not another delivery gate.
