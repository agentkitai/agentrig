# H5 — Memory lifecycle and auxiliary work

Deliver H5a → H5b → H5c → H5d as separate, sequential PRs from CI-green updated main. See the
roadmap for acceptance. H5a primitives are not a claim that every maintenance caller is migrated.
H5b is further split into H5b1 persistence/stale captures/pins/log recovery and H5b2 bounded
provider/backend cancellation and auxiliary accounting. These are sequential PRs with the same gates.

## H5a boundary

Reads expose a content-hash version (first 128 bits of SHA-256) of the exact persisted page.
This is a content token, not a monotonic generation: identical rewrites and exact reverts share it.
Agent-visible replacement tools accept `if_version` from that read or the previous write receipt;
absent/null means create-only, not blind overwrite. Conflict
responses carry the current page and token so the caller can merge and retry intentionally.
Trusted SDK unconditional writes remain available for compatibility, explicitly not conflict-safe
read/modify/write. Add a synchronous-transform update primitive for maintenance migration in H5b.
CAS transforms derive metadata inside the version-checked lock. Once a page rename commits, its
index bookkeeping finishes without another cancellation check; an index I/O failure returns a
committed result with a warning. Lock-release failures cannot replace the operation's result or
primary error: CAS exposes warnings on returned results; all callers also receive `onReleaseError`
or a process warning, including when an operation throws before returning a result.

Serialize short store mutations using an exclusive lock shared across processes and canonical
root aliases. Bound lock waits with a real elapsed clock, independent of an injected content date.
Never reclaim by age: a slow live owner must not lose its lock. Crashed-owner locks fail closed
with an actionable path for operator recovery. Locks protect cooperating writers, not hostile
hosts, arbitrary editors, or multi-file crash transactions. Dream swaps need H5c integration.
All cooperating writers must use the new lock protocol; stop older running harnesses during upgrade
because historical releases used a separate index-only lock.
Initialization uses its existing mkdir/O_EXCL primitives and does not take the write lock, so
read-only CLI inspection remains available during recovery. Parent-directory permission failures
name the sibling lock path; Windows delete-pending access errors get a separate 250 ms retry
window within the overall wait bound. Failed identity capture retries during release; if ownership
still cannot be established, preserve the lock and report its path for stopped-writer recovery.

Index/log updates and reservations use the same mutation discipline. Real generated placeholders
are bookkeeping, not durable facts; lint/index rebuild must preserve their planned claimant state.
Aliases already exist in frontmatter/search: retain them and clarify index hints are not proof of
absence without opening the page.

Test real conflicting versions, create races, raw-content edits, multiple store instances and
separate processes, lock timeout/abort, index/log conservation, aliases, and real reserved pages.
Mutation-test the CAS check. Run build/typecheck/full suite, independent review, PR CI, merge and
main CI before H5b.

The separate-process regression imports the production build; run `pnpm build` before that suite
or the full test run. CI already builds first. The remaining in-process tests use source aliases.

## H5b1 boundary

Ingest and backend provenance derive page mutations from the current page inside the short shared
mutation lock, preserving facts, aliases and sources from competing writers. Annotated fact lines
still count as the same fact on retry. Both replacement tools recheck pins through one path.
Pin additions and status writes share the page lock; checked pin snapshots include page versions,
so old checks cannot overwrite a changed page/pin or resurrect a removed pin. Unversioned external
checks are inspection-only; use `recheckStoredPins` for a fresh persisted result. Malformed pages
or pins fail visibly rather than being mistaken for absence.
`applyPinChecks` accepts the inspected store (or a root for compatibility) and returns per-input-check
applied/skipped counts, including already-current/duplicate checks rather than distinct pins written.
Checks compare against the original guarded snapshot, including status-changing duplicates.
Lock timeout options are independent of the supplied store constructor and must be passed explicitly.
Dream carries these counts in its returned/rendered report, so missing callbacks cannot hide skips;
skips count as findings rather than a clean dream. A conflict and skipped persistence are separate
issues even for the same pin. Tests prove its output pins change without changing the input.
Malformed pinned pages abort a dream visibly,
not with a false orphan status. Unchanged statuses are not rewritten. The empty-pin snapshot fast
path is intentional: it performs no mutation, and pins added after that snapshot belong to a later
operation; page replacement and future human pin additions are not one atomic transaction.
Pin matching excludes bookkeeping comments, so the final metadata-only capture write does not
change the visible claims/anchors just checked. Statuses describe the checked snapshot, not a
promise that later writers can never change a page.
On the first recheck after upgrade, pins previously satisfied only by bookkeeping comments may
change from active to conflict (or comment-anchored pins to orphaned) without any page edit. This is
an intentional correction of false matches; the human pin itself is retained.

Same-session ingests additionally hold `${canonicalWikiRoot}.ingest-${sessionHash}.write.lock`.
The key is the first 128 bits of SHA-256 and folds ASCII case to serialize source-file aliases
on case-insensitive filesystems (it conservatively serializes those aliases on Linux too).
Session IDs follow core's filename contract.
The wait is bounded by `lockTimeoutMs` (default five seconds), with no stealing; interrupted owners
require stopped-writer manual recovery: after a crash, stop all writers and remove the exact named
ingest lock before retrying. Do not delete a live owner's lock; a timeout can simply mean another
ingest is still distilling. `signal` cancels acquisition/waiting only in H5b1, and the session-end hook
passes it through; it does not yet cancel an entered provider or subsequent commits. Page/index/log
paths are created lazily for SDK callers; a full skeleton including overview still needs `init()`.
Distinct sessions can distill concurrently, and provider/backend calls never hold the short wiki
mutation lock. These calls themselves are not yet bounded
or cancelable here: that is H5b2, which must also prevent post-cancellation commits.

Completed captures retain per-event hashes, allowing strictly shorter raw prefixes to be skipped
even when canonical messages replaced earlier streamed transcript projections. Older captures
without those hashes are reprocessed once. A growing capture retains previous narrative rather
than trusting a fresh distillation to repeat all earlier facts. These mutable capture markers are
maintenance bookkeeping, not immutable evidence or the H4 promotion gate. H5b2 bounds capture/input
size; hash metadata currently grows with the captured event count.
Only the final generated trailer controls completion; marker-shaped narrative text is not parsed
as metadata. The older `capture:prefix` field remains compatibility-only. The historical result
field `supersededPrevious` means an extended raw capture, not deletion of earlier narrative.
New fact/summary line breaks are normalized to spaces so downstream fact parsing retains every
claim and its source refs; existing narrative's interior blank lines are preserved. No-findings
text is a comment, not a ref-less fact, and the exact old sentinel is removed when rebuilding.
Trailing standalone capture/ingest comments use reserved bookkeeping syntax and may be removed;
use a blockquote or fenced code block for marker-shaped human notes that must remain literal.
Text appended after a trailer causes that old block to remain as interior comments, with a fresh
trailer added on the next ingest.
This deliberately preserves interior narrative; repeated such edits can retain extra metadata,
whose input/size bounds remain H5b2.

The source stays explicitly pending until local page/index/pin/log mutations finish; only then is
the completed capture marker written. Interrupted runs can be retried without dropping facts or
being skipped as completed. This is not a multi-file transaction: partial pages remain inspectable,
and an interruption after a log append can produce a repeated chronology entry on retry. Optional
backend delivery/annotation remains best effort after local completion, not exactly-once delivery
or a durable retry queue. A completed local capture is not replayed solely to retry its backend.
Annotation currently adds only the first backend reference to a fact; it is not a multi-backend
provenance merger.

Log appends recover empty or known partial initialization headers while retaining existing entries
and custom notes, and separate the new entry from a missing trailing newline. Tests cover real
cross-process ingest/pin writers, blocked-provider edits, stale captures, interrupted retry,
provenance, changed/deleted pin snapshots, malformed data and log recovery. Build before fork
fixtures; Windows CI executes these persistence tests too.

## Remaining lifecycle work

H5b migrates ingest/provenance/pins to conflict-safe commits, fixes shorter stale-capture handling,
and carries bounded cancellation and auxiliary usage through provider/backend calls. It also
recovers empty/partially initialized log headers without losing existing entries, with deterministic
recovery tests (the H5a ENOENT/init race test does not cover truncation). H5c applies
the same contract to dream copies/apply and investigates CI 33952067241's staged-abort timeout.
H5d integrates reviewer/grader lifetimes and explicit main/auxiliary/unknown accounting. Shared
contracts must preserve memory/supervisor's type-only dependency on core; no hidden import of the
agent runtime. Cancellation cannot undo a commit already made, but must prevent later commits.
Existing dream apply does not participate in the mutation lock at all: it must not run concurrently
with writers until H5c lands. H5c also owns cleanup of crash-left sibling locks for dream workspaces;
normal disposal alone cannot recover abnormal exits. Design explicit ownership-checked recovery
for crash-left workspaces; never blindly sweep or unlink active/replacement owners. Placeholder generation,
fact classification and ingest stripping now share one definition; this is not ingest concurrency
migration.
