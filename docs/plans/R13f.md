# R13f — corroborated supervisor progress

## Contract

File-change events remain available to every registered tool and remain immutable log claims.
Core stamps `file.changed.toolCallSeq` from the executing runtime call, overwriting any supplied
value. A normal completed `tool.result` carries that same call sequence and the resolved permission
class used for approval. These fields are optional for old-log compatibility. Provider call IDs
alone are insufficient because a provider can reuse them.

The supervisor queues claims until a matching successful **write-class** result in the same turn.
Only then do loop/stall detectors and the policy's `filesChanged` counter receive progress credit.
Read, exec, network, missing provenance, failed/aborted/missing results, stale calls, late claims,
and claims crossing a turn/session boundary receive none. A result consumes its pending receipt
once. At most 400 pending calls and 400 claims per call are retained; excess evidence receives no
credit. Permission class is trusted host configuration, not proof the file was actually written.
This row intentionally does not infer writes from shell prose or treat exec as write.

Drift additionally prepares current-worktree evidence before classifying a claim against scope.
The optional `Detector.prepare(event, state, signal)` seam is awaited by `attach` before `observe`;
other detectors remain synchronous. Direct drift SDK callers must use this preparation as well.
All findings from one multi-file result are retained in the combined signal, including contract paths.
Missing/failed preparation is fail-closed. Verification checks at most 32 claims per result, at
most 1 MiB per regular file, and has a one-second total observation deadline plus supervisor
cancellation. It rejects absent/unreadable/oversized/non-regular files, mismatched hashes, outside
paths and symlink escapes. Accepted paths are made worktree-relative before scope comparison.
No model calls, permissions, or file mutations are introduced by verification.

Cancellation/deadline races can leave an already-issued read-only OS operation settling; late
completion cannot grant evidence. File handles close when those operations settle. Ordinary local
filesystems are assumed: this is not an OS sandbox or a guarantee against concurrent hostile path
replacement. Stable size/mtime and bounded reads reduce, but do not eliminate, external races.

Current bytes prove only that the claimed content exists when checked, not authorship or historical
state. A later legitimate rewrite may make an earlier claim unverifiable. Deleted files remain
unknown for drift: absence alone does not prove prior existence. These limits cannot mint progress
from a read-class claim. General trust labels, parsed-operation permissions and prior-state deletion
witnesses are not bundled into this row.

## Validation and delivery

- Real agent + immutable SessionStore replay: repeated injected read-tool claims trigger the same
  loop/stall signals at the same turns as silent reads; caller-supplied provenance is overwritten.
- Positive control: registered write-class receipts preserve progress, even with repeated provider IDs.
- Actual `attach` + built-in `write_file`: worktree-verified out-of-scope write produces drift.
- Reducer controls: missing/failed/legacy/mismatched/replayed/cross-turn/late claims and bounded queues.
- Real-filesystem controls: matching/mismatching content, scope, absolute paths, missing files,
  directories, oversize, deletion and parent symlink escape; cancellation/deadline and late read result.
- Legacy detector fixtures now explicitly carry write receipts. H6 golden traces change only for
  the two additive result fields; the event ordering and old payloads stay unchanged.
- Build, typecheck, full suite, one bounded independent review, named negative mutation restored,
  and exact-head Linux/macOS/Windows CI required before merge. The closing PR records receipts.

Local negative controls removed the write-class requirement (the actual injected-agent test lost
all expected loop/stall signals) and bypassed the content hash (the mismatch control wrongly
reported drift). Both mutations were restored. One independent Claude review approved with no
material findings; session `2fdeec4f-21ca-4b77-91be-60b0d6d14088`, 162 independently run tests.
Final self-check additionally retained all multi-file batch evidence and added a portable pre-open
regular-file check; the closing validation reruns cover the final artifact.
