## Input and schema boundary

- `run --output-schema <path>` means an explicit local JSON-schema file, not inline
  JSON, an expression or a URL. It composes with ordinary run and `--ci`; it is not
  a project-config key or inherited child constraint. Without the flag, behavior
  is unchanged. Resume requires the operator to supply the constraint again;
  historical events never reauthorize it.
- Stable regular non-symlink fatal-UTF-8 input, at most 32 KiB, JSON depth 12,
  at most 512 schema nodes. Validate before provider/startup work. Diagnostic
  categories are fixed and do not echo schema values, response text or raw errors.
  Duplicate object keys, including escaped equivalents, are malformed, not last-wins.
- Initial documented JSON-Schema vocabulary: boolean schemas; `type` (single type
  or nullable type pair), `properties`, `required`, `additionalProperties`
  (boolean or schema), homogeneous `items`, `enum`, `const`, `minimum`, `maximum`,
  `exclusiveMinimum`, `exclusiveMaximum`, `minLength`, `maxLength`, `minItems`,
  `maxItems`. Optional `$schema` accepts only the pinned 2020-12 identifier.
  Unknown keywords refuse rather than being silently ignored. No refs (including
  local), recursive/combinatorial schemas, regex/format, defaults, coercion,
  removal of properties, asynchronous validators, plugins or network loading.
- Reuse maintained AJV 8.20.0 with a direct core dependency and strict compilation,
  `allErrors:false`, no data mutation. Bound input text to 64 KiB and parsed output
  depth 32 before validation. No fallback to partial JSON, Markdown-fence stripping
  or regex extraction: the complete final assistant text must parse and validate.
  The supported subset and limits are visible in CLI help/operator docs, not a
  claim of arbitrary full-draft support. User-selected schemas are still explicit
  operator inputs, not a sandbox for hostile JavaScript or unlimited workloads.

## Runtime and provider use

- Core owns validation through an optional validated output contract on the agent;
  the CLI loads the file and wires it, not a second loop. Final text is assessed
  only on a completed no-tool assistant response, after existing raw messages and
  events have been recorded. Refusal/error/abort do not become repair candidates.
- One invalid completed final answer permits at most **one additional ordinary
  budgeted model iteration**, if existing turn/token/time/USD/abort/pre-model gates
  allow it. No limit increase, reset or fresh user message. The repair instruction
  has platform/advisory provenance and keeps the R13c restriction intact.
- That repair advertises no tools and independently blocks actual dispatch of
  every returned tool call before any tool callback/strategy. Unexpected calls get
  paired non-execution results, then an error; no orphan IDs or deferred execution.
  Repair truncation/error/invalid JSON ends nonzero, without H7a continuations
  multiplying the single repair allowance. Ordinary H7a behavior outside repair
  stays unchanged. A new user run is a new explicit attempt, not hidden retrying.
- Native opt-in: `--output-mode prompted|native` with prompted default.
  Native requires the actual OpenAI-compatible Chat Completions adapter and an
  explicit trusted constructor capability; the CLI operator flag enables that
  capability on this actual instance for this run, not verified server support.
  No model-name/endpoint/probe inference.
  `native` maps the neutral schema to `response_format:{type:"json_schema",
  json_schema:{name:"agentrig_output",strict:true,schema}}`. Other adapters refuse
  explicit native mode and continue to support the prompted/local-validation path.
  The experimental ChatGPT backend gets no undocumented native field.
- Native-compatible schemas additionally require an object root, all properties
  required and `additionalProperties:false` throughout object nodes, with the
  documented supported keyword subset. Reject incompatible schemas before calls;
  never rewrite optionality or broaden the user's schema to fit the provider.
  Every native response is still locally validated; server refusal or unsupported
  model errors remain errors, not proof or silent paid fallback.

## Output and audit

- Add a protected typed validation event with schema digest, native/prompted mode,
  attempt (initial/repair), valid/invalid and a fixed bounded error category; no
  response/schema prose in the event. Render chat/trace and preserve export
  compatibility. An event is observation, not permission or acceptance evidence.
- Terminal invalid output sets runtime reason error and CLI nonzero. Raw deltas,
  original invalid text and repair text remain in append-only logs/snapshots;
  nothing is scrubbed, overwritten or presented as independently verified truth.
  Ordinary streaming/`--json` remains streaming, not a promise that every stdout
  byte is final JSON. CI retains its bounded inert report and refuses comments on
  invalid/error outcomes; validation counts/status can appear without raw prose.
- Budget/veto/cancel before a repair request cannot emit an event claiming it ran.
  Session-end hooks and cleanup still run once. Pending background/auxiliary work
  retains existing accounting/ownership semantics; the row adds no billing claims.
