Successful actual built-in edit/write operations attach captured before/after
observations to their canonical result events. A private factory identity and
result/context receipt prevent a same-named extension or JSON result field from
claiming a builtin observation. Capture occurs inside authorized execution;
rendering never reads files or invokes Git. Diagnostics and post-tool display
rewrites do not replace the original captured observation. Model messages and
metadata-only telemetry do not acquire this content; canonical raw logs are
sensitive and do retain it. This is an observation, not a filesystem transaction,
writer-isolation proof, or assurance about later disk state.

Capture retains at most 64 KiB UTF-8 and 6,000 lines per side; paths at most 4,096
characters. Truncation is explicit. Existing edit-file reads are unchanged; the
additional write-file before read uses a bounded regular-file handle and refuses
symlinks/nonregular files for observation, without changing existing write
authorization. While an enforcing sandbox is active the additional host-side
write-before read is skipped and reported unknown; no new read bypass is added.
Missing before is empty only for an initial observed ENOENT; unreadable,
binary, unsupported, or raced observations remain unknown, never invented
deletions. After comes from the exact successful write input, not a reread.

Permission asks use the same renderer with a different explicit scope: edit input
is a proposed replacement excerpt (not whole-file before/after); write input is
proposed content with unknown prior contents. Preview performs no filesystem
reads and cannot grant permission. Only actual builtin identity derives it from
validated input; declared effects remain alongside it. Denial has no write or
before-read effects.

Use pinned jsdiff structuredPatch with context 3 and maxEditLength 2,000 over
bounded captured strings. Aborted/high-complexity comparisons render labelled
before/after excerpts, not a purported minimal patch. Output has at most 80 lines
per file (including explicit elision), 512 printable characters per line and
48 KiB overall. Unknown sides and truncated snapshots are visibly labelled.
Added/removed/context and hunk headers use only fixed application ANSI codes;
source terminal controls and bidi controls are sanitized, NO_COLOR respected.
No applying patches, new diff framework, editable views, or wrapping outside the
existing viewport. Bounds do not claim hard CPU/RSS containment.
