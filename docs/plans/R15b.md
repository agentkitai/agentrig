## Contract

Optional trusted `diagnostics` configuration holds at most eight checkers, each with
explicit extensions and one parser (`tsc`, `ruff-json`, `go-vet`). Duplicate extension
ownership refuses. Executable and at most32 literal arguments are bounded to4096
characters each and16KiB combined. No shell interpolation, templates, automatic
installation, language-server daemon or index. Native executables (or e.g. `node` plus
the compiler script) avoid platform-specific shell shims. Config is not exec consent.

Each checker has250–30000ms timeout (default10000), combined output4096–262144 bytes
(default65536). The existing owned JobRegistry/process-group/taskkill infrastructure
is reused with a smaller buffer and stop-on-overflow. Cancellation joins the owned
process; escapees/hostile daemons are not proven contained. Sandbox process wrapping
and ordinary exec policy/grants/fresh external-input consent all remain mandatory.

Only actual builtin write/edit factories can mint a process-local result/context-bound
changed-file receipt. Capture the resolved path and intended written hash, verify bytes
before and after checking; mismatch/missing/over16MiB source is unknown, never checked
current bytes. A concurrent writer can change/restore between observations: this is
cooperative observation, not transactional filesystem attestation. Failed edits do not
run a checker. No matching extension or disabled configuration preserves legacy behavior.

Enabled edit/checker pairs are conservatively exclusive under parallel scheduling. The
outer lease remains held; private checker dispatch uses the same ordinary execution
pipeline without reacquiring that lease. Unique runtime IDs and parent correlation
mark internal calls/results in the immutable audit. Nothing registers a model tool,
and internal events cannot produce unmatched conversation tool results on replay,
resume, fork or compaction. Only the original result carries optional `diagnostics`.
Actual checker output is captured before output hooks; modified executable/argv cannot
pretend to be the configured command. Checker failures never undo/retry a successful
write. No recursive checker chain or background checker is available.

## Observation, not proof

Supported formats are nonpretty `file(line,column): error TS123: message`, Ruff JSON
filename/location/code/message entries, and `file:line[:column]: message`. Lines over
8192 characters and unmatched text are unknown. Canonical exact-file matching separates
other-file findings; project-only errors are explicit, not a clean file verdict. At most
100 findings with1024-character messages are retained, with visible omission/incomplete
status and bounded rendered output. Zero exit/empty recognized output means only
"no diagnostics reported", never correctness. Denied/failed/aborted/timed-out/truncated
or unrecognized checks stay unavailable/incomplete. Output is tool-origin data, never
permission or sandbox proof. Export redacts diagnostic strings with other content.
