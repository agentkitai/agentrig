## Contract

`AgentConfig.turnStrategy?: TurnStrategy` is trusted host SDK injection. The exported
`sequential` object is the default. `execute(calls, { signal, runTool })` receives complete
model calls and returns `{ results, interrupted }`. It only schedules the existing tool
pipeline; schema/hook processing, authorization and receipts, provenance, sandbox,
checkpointing, output limits and event sequencing remain in `executeTool`/session lifecycle.
No model-selected strategy, CLI code-loading option, provider-specific loop or parallel
implementation is added. Provider `parallelTools` describes model protocol support, not
an opt-in to concurrent execution. R10b/R10c retain their own later acceptance checks.

The loop owns model response handling, budgets, continuation, compaction and message
assembly. `max_tokens` responses never reach an injected strategy; their non-execution
results and continuation remain in the existing loop. Empty non-truncated responses end
without a strategy call. Resume uses the current trusted AgentConfig, not log-replayed code.

Sequential awaits each runTool result before starting the next callback. Cancellation is
checked before each call, preserving the existing asymmetry: abort before a later call
interrupts the turn and discards the partial batch from conversation append (individual
tool/audit events remain). Abort during the final call still follows the prior result-batch
append path. An empty batch is a no-op, including with an already-aborted signal.
The loop emits the same interrupted turn-end event; no strategy events are introduced.

Custom strategies are trusted ambient host JavaScript, like other SDK integrations, not
a sandbox for hostile code. They must preserve call/result correspondence, use the supplied
pipeline, cooperate with cancellation and join their dispatched work before returning;
no timeout abandons in-flight effects. A rejected strategy follows existing fatal-error
settlement. These responsibilities are not claimed as enforcement against arbitrary host
callbacks or prematurely returned background work. Built-in subagents retain their existing
child config/default strategy unless a host explicitly configures a strategy there.

```ts
import { createAgent, sequential } from "@agentkitai/agentrig-core";
const agent = createAgent({ ...config, turnStrategy: sequential });
```
