# R13a — content trust metadata transport

## Scope and ordering

R13a is independent transport/retention groundwork, implemented in its own worktree after R13f
main `1a20f4e`. It can proceed alongside permission work (R12e/R12a) and procedure detection
(R6a): it grants no permissions and changes no wiki schema. R13b's assembly/compaction rules,
R13d's principals and R13c's enforcement are separate dependent rows, not claimed here.

## Contract

Every unified ContentBlock variant gains optional `trust`: `user`, `project`, `external`,
`tool-output`, or `generated`. Recursive tool-result content uses the same schema. Public
`ContentTrustSchema` validates the enum; legacy absence stays absent and invalid values reject
instead of silently disappearing. Labels are host-supplied provenance metadata, not authenticated
principals, permission grants, a trust ordering, or evidence that content is safe.

Typed custom-provider text deltas/tool calls may supply the optional metadata. Core validates it
before building a canonical assistant message. Adjacent text with distinct labels remains in
distinct blocks; same-label fragments concatenate normally. Canonical message.append events,
snapshots, materialization/fork ancestry, subsequent requests and resume retain those blocks.
Raw text-delta events remain unchanged; the canonical message event is the labeled record.
If a crash leaves only raw deltas before a canonical append, legacy reconstruction is unlabeled;
it does not invent metadata that was never recorded in those events.
Invalid custom-provider labels end the run as an error without appending malformed messages.

The built-in Anthropic, OpenAI-compatible and ChatGPT Responses adapters preserve unified input
objects while explicitly projecting supported wire fields. They do not export our labels as
unsupported vendor fields or prompt text. Vendor/model-controlled extra JSON fields or prose
never become host labels. Existing raw Responses reasoning items remain an opaque vendor cache,
independent of unified provenance, not an authority source. All tests use injected local fetch
responses and fixture-only authentication; no live calls or real credentials are needed.

Hook observation copies recursive content blocks so an observing hook cannot mutate stored
nested labels through a shared array. For labeled responses, post_model sees the complete
segmented content; unlabeled legacy hook observations remain unchanged. Outbound tool-result
eviction preserves the outer label. A result with labeled nested blocks is kept intact instead
of flattening and silently dropping its metadata. This may increase request size for explicitly
labeled large payloads; no trust aggregation is guessed here.

Automatic origin classification and lowest-trust inheritance for **new compaction summaries**
are R13b. Existing retained task/tail blocks and historical log messages keep their metadata,
but R13a does not certify provenance of newly synthesized summaries or infer labels from text.
General hook delegation and hostile in-process provider code remain separate trust-boundary work.

## Acceptance and delivery

- Public-schema fixtures: every enum/variant, recursive labels, invalid and legacy controls.
- Real SessionStore round-trips, event materialization, fork ancestry and actual agent resume.
- Scripted custom-provider turn with multiple text provenance segments and a labeled tool call;
  hook observation, next request, immutable message and snapshot agree.
- Actual fetch-backed adapter transformations equal their unlabeled wire projections and leave
  source messages unchanged; forged vendor text/tool-call labels do not enter ModelEvents.
- Eviction and hook-copy controls retain nested metadata; invalid custom-provider metadata leaves
  readable canonical JSONL and a failed session.
- A named drop-label mutation must fail and be restored. Build/typecheck/full suite, one bounded
  independent review and exact-head Linux/macOS/Windows CI precede the coordinator's merge.
  Exact post-merge CI precedes the next merge. The closing PR records final receipts.
