# R13c — external-input permission expansion guard

This is one coarse enforced guard, not a permission framework or a solution to prompt injection.
Three first-actual-dispatch categories are tracked per run: exec, network, and write outside or
unknown relative to cwd. A grant, proposed tool.call, denied call or sandbox-preparation refusal
does not open a category. Actual invocation opens it even if execution subsequently fails.
Resume starts empty; no log receipt restores this live state. No argv/URL/path-history claim.

New input is runtime-delivered non-model content since the preceding request boundary, not old
task/history text. External, generated, tool-output and unlabeled ancestry is conservative;
recursive user/project source labels alone do not clear an existing restriction. Restriction is
sticky through no-new-input continuations and compaction. Only an actual fresh nonempty user task
or delivered user steer clears it; roles, stored/returned context labels, prose and hook delegation
cannot manufacture fresh user input. A request containing actual fresh user input is the explicit
mixed-input exception; this does not claim semantic intent attribution.

Under restriction, first-category expansion requires fresh separate consent despite blanket/yolo,
standing or scoped grants. Explicit policy denial still wins. No interactive callback means deny;
only explicit fresh allow succeeds. SDK onAsk is a trusted human-approval seam, not proof that an
arbitrary host callback really asked a person. The reserved external-input-expansion origin cannot
be remembered, and original child provenance is preserved separately. Distinct permission.expansion
events audit the decision. Approval alone never marks actual dispatch.

Write classification reuses the existing bounded canonical write-target resolver, including new
files, missing parents and dangling symlinks. Missing declarations, errors, over-budget or
unverifiable containment require approval. This trusts registered permission/path declarations
and observes the filesystem; it does not attest tool effects, external-writer races or hardlink
aliases, and it does not replace sandbox enforcement.

A bounded heuristic injection detector scans explicitly external canonical content and summaries
for instruction-shaped phrases/tool syntax. It emits an advisory injection signal, with false
positives/negatives explicitly possible. It never creates authority or supplies the enforced guard.

Acceptance: actual same-action user-versus-external and summary-laundering pairs; sticky state,
fresh-user reset, per-category/actual-dispatch/resume cases; canonical/symlink/unknown write paths;
fresh approval bypass/denial/cancellation, child attribution and UI no-standing/no-yolo controls;
real supervisor attachment, schemas/rendering, named restored mutation controls, full checks and
one bounded independent Claude review. Each exact updated-main head needs all-platform CI; root
merges and post-merge CI gates dependent work. Optional polish belongs at ROADMAP's end.
