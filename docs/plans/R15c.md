# R15c — persisted reasoning blocks

Started from updated, four-check-green main `3174475` (R15a repair #191).

## Contract before implementation

Add a unified `thinking` content block carrying provider-disclosed display text and
bounded, provider-opaque replay material, including signature/item identity. This
is returned provider data, never new human instruction, a tool, or permission.
Core persists and orders blocks without interpreting a vendor payload. Adapters
alone validate and translate their replay format. Existing logs remain valid.

Anthropic thinking/signature deltas and redacted-thinking blocks must survive
completed-block parsing, actual tool turns, snapshots, logs, fork and resume.
An empty disclosed text is valid; encrypted signatures/data are not display text.
OpenAI Responses reasoning items must survive independently of the existing
in-memory tool-call replay cache, including reasoning-only turns and a fresh
provider instance on resume. Emit each returned reasoning item exactly once in
the next compatible request, in its original content order. No decryption or
invented thinking text. No provider/model migration or automatic thinking setting.

The legacy Chat Completions adapter has no supported reasoning replay field in
this repository. It must explicitly refuse incompatible thinking history before
network I/O, as must cross-format replay and malformed opaque material. Do not
silently drop it, serialize it as user prose, or invent vendor fields. Provider
format compatibility is not a guarantee that every model/account accepts a block.

Bound each added replay block and cumulative per-turn reasoning retention before
growth; reject overflow explicitly, never truncate a signature then replay it.
Opaque bytes remain in the private canonical log/snapshot as required for resume.
Normal rendering, telemetry, memory extraction, reports and summaries must not
serialize them. TUI shows a collapsed thinking marker and reveals only disclosed
text with `/verbose`, never the signature/encrypted payload. JSON event logs are
raw audit data and remain sensitive, not a redacted export.

Export omits thinking first with an explicit lossy marker/count, including its
disclosed text, without disturbing retained tool-use/result pairs. Compaction may
evict reasoning from older completed rounds before building the summary request;
preserve the retained recent tool pairs and their reasoning verbatim. The new
advisory summary is the explicit context boundary, not a new human instruction.
Never send opaque material to a summarizer
or mutate immutable source logs. Keep provenance floors and existing task/tool
pair boundaries. No claim that retained ciphertext has zero context cost.

## Implementation and author controls before independent review

Added limits: 256 KiB serialized replay, 64 Ki characters disclosed text, 256 Ki
characters signature, 256 characters ID, 512 KiB complete envelope; at most 32
thinking blocks and 1 MiB retained reasoning envelopes per core turn. Adapters
also bound their added reasoning accumulation; existing general SSE framing and
canonical log size are not newly claimed to be total-memory-bounded. Malformed
UTF-8, missing Anthropic signatures and crossed signature-block boundaries refuse.

The Responses provider's hidden raw-item cache was removed, not merely bypassed:
otherwise compaction could remove a block only for the cache to resurrect it.
An explicitly supplied legacy raw-group argument to the exported request helper
remains compatible, but the runtime never supplies it. Existing logs that already
lost reasoning cannot reconstruct missing bytes. This row preserves reasoning
items, not arbitrary non-reasoning vendor annotations or assistant-item metadata.

Actual Anthropic/Responses SSE tool sessions preserve exact returned items in the
second request, canonical log, snapshot, fresh-provider resume and fork. The old
Responses replay test now feeds its actually parsed thinking events into history,
retaining its exact-once/order assertions rather than relying on hidden state.
One-byte UTF-8 streams, malformed encoding, wrong formats/roles/nesting, forged
display text, overflow and incomplete/crossed blocks have negative controls.
Mounted Ink fixtures check default collapse and explicit verbose disclosed text;
export, memory and supervisor controls exclude both signature and disclosed text.

Local E1-style controlled acknowledgement: both adapters map omitted reasoning to
0 cached tokens and retained byte-identical reasoning to 20, with total input 40
unchanged. This is a deterministic fixture rule and conservation check, NOT measured
provider cache performance. Actual live cache delta remains unmeasured.

Two mutants were detected and restored: removing the core thinking append fails
both actual second-request replay controls; returning the thinking block from the
exporter fails on the opaque secret canary. Initial test-harness mistakes were a
fake token store with load/save instead of read/write and an Ink stdin without raw
mode support; corrected fixtures pass without production workaround. Initial ordered
build/typecheck/full actual-Docker run passed 2,835 tests plus two existing skips,
173 files, four workers, 54.30 seconds. Final UTF-8/boundary hardening and its new
controls require the frozen-head full rerun below; do not attribute that earlier
full result to later edits. No live provider or collector calls.

## Independent review and bounded correction

One Claude review requested changes for compaction. Requested 24 turns, reported
27, 251.759 seconds; independently ran 52 focused tests and four-package typecheck.
No independent full suite or reproduction (two ad-hoc shell commands were denied).
[Original verdict/findings, verbatim](R15c-review.md). No second review.
Frozen `20e9388` separately passed author build/typecheck and full Docker validation:
2,838 passed plus two existing skips, 173 files, 52.44 seconds, four workers.

The material finding was reproduced on the reviewed production code by three new
controls: both single-task and multi-user shapes made zero summary calls; the actual
single-task ten-tool-round agent also never summarized. The original whole-task
reasoning clamp and eviction-only early return were incorrect: the former prevented
single-task compaction, the latter could latch the runtime's no-progress guard.
The corrected contract preserves the retained recent tool pairs and their reasoning
after a new advisory summary, not every round since the initial user task. Older
thinking is omitted before the summary request and normal summarization completes
in the same operation. No changes to the runtime's ten-percent progress check,
authority/provenance rules, raw logs, or tool-pair tail boundary.

The same controls now require one-call reduction greater than ten percent, exact
retained tail, immutable original history, and repeated actual runtime compaction
without exhaustion. They also prohibit opaque/disclosed thinking in summary inputs.
This is author fail-before/pass-after evidence, not a reviewer reproduction or a
new independent approval. Optional placeholder-label concern disappears with the
removed early-return branch; the stale roadmap comparison is updated below.
Anthropic configuration/provider-specific live behavior remains an explicit
limitation rather than an invented offline guarantee. Final integrated full-suite
and PR/post-main gates remain required.

The first actual-runtime reproduction fixture reported a fixed 100 input tokens,
so it did not cross the compaction threshold at all; that failure alone was not
evidence of the guard defect. After making reported usage reflect request size,
all three controls were rerun against the exact frozen `20e9388` compaction file:
all failed, and the runtime emitted its permanent no-progress warning. Restoring
the corrected file made all three pass, including repeated actual compaction.

Author integration audit also reproduced a preflight gap: incompatible Responses
history caused one credential read and one fake OAuth refresh before request-builder
refusal. Validation now precedes authentication; the same expired-token control
requires zero credential reads, refreshes and provider requests. This is a bounded
author-found correction to the existing before-network contract, not a second
review. All calls in this control use injected functions, no real credentials/network.

Integrated green R15d main `8da49d4` at `50fbda1`; only roadmap/status conflicts,
with runtime changes composing mechanically. Before the additional preflight fix,
install/build/typecheck/full Docker passed **2,872 tests plus two existing skips,
177 files, 59.91 seconds**. Final preflight-fix validation follows, not implied by
that prior result. R15d completion is retained in roadmap top/row/§5 and STATUS.
