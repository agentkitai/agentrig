# R12c — Live grant inspection and decision attribution

## Contract

`/permissions` lists live grant IDs, exact operation/resource/constraints/duration/subject and
delegable metadata, age in seconds and matched-decision count. Existing `reset` clears all;
`revoke <exact-id>` revokes one. Prefix IDs, unknown IDs and malformed commands never broaden
into bulk revocation. Revocation changes the next permission decision, not tools already
authorized/running. Existing bounded audit queues retain unrecorded revocations on append
failure; no after-terminal log writes or authority replay are added.

A hit means a live allow/deny grant actually matched at the runtime authorization boundary.
It does **not** mean a tool executed or succeeded: later checkpoints, cancellation, audit writes
or execution can fail. The first prompted call is decided by the approval handler, not by the
grant it just created, and has zero grant hits. Pure previews, `decide`, inspection and explicit
base-policy decisions do not count. Counts are process-local and shared with the current child
group, not reconstructed from log history. R12d owns inheritance filtering. Counters saturate
at `Number.MAX_SAFE_INTEGER` and display `>=` rather than wrap or claim an exact larger value.

`PermissionGrantRegistry.inspect()` returns cloned live records and counts. `authorize()`
returns the actual matched grant ID/decision and counts it once. Its optional `deny-only` mode
supports a separate fresh-consent guard honoring an existing deny while overriding an allow;
an inspected allow is then not counted as consumed authority. This row supplies the small count
seam, not R13c's policy. Failed/unflushed grant audits still prevent grant-derived dispatch.

## Same-call attribution

`PermissionPolicy.decide(req, report?)` retains its original return type. Existing one-argument
custom policies and subclasses remain valid and are called once; the optional callback is
diagnostic, never an authorization decision. `RulePolicy` reports the actual one-based first
matched rule index and cloned rule snapshot, or fallback. Indices identify the evaluated policy
instance's ordered rules, not a stable global configuration ID.

`evaluatePermissionPolicy` captures a bounded strict receipt during that same evaluation and
checks its reported decision against the actual result (and nested rule decision). Missing,
malformed, multiple, mismatched, or post-evaluation receipts yield honest unknown attribution.
Captured data is cloned by validation, and callbacks after evaluation closes are ignored.
There is no async policy rerun or retrospective inference from tool/model text. Arbitrary SDK
policy code remains trusted and can lie; diagnostics are not a sandbox for host JavaScript.

Optional `permission.decision` fields `toolUseId`, `tool` and `source` correlate the result with
the call. Sources distinguish actual rule, fallback, matched grant, approval handler, unattended
deny, boundary and unknown. `onAsk` is labeled **approval handler (human/host)**, not asserted to
be a human: SDKs may supply automated handlers. Registry session/audit blockers replace stale
allow attribution. A separate fresh-consent restriction must retain an explicit winning deny;
otherwise boundary/handler attribution replaces the superseded allow, never claims it executed.
R13c integrates that policy separately. Existing sandbox/MCP separate consent remains unchanged.

Chat and trace views show the captured source for decisions without evaluating any policy.
Legacy events without source remain readable and gain no invented attribution. Source schema
fields are bounded/strict; existing correlated call/name fields retain their event compatibility.
Configured rule/grant scope details appear in local logs/UI like existing grant records; they
should not contain secrets. There are no new provider calls, event kinds or persisted grants.

## Verification

Tests discriminate first-match rule/fallback, one-call custom/subclass behavior, malformed and
late receipts, cloning, explicit-rule precedence, grant hits versus previews and failed tools,
deny-only consumption and immediate revocation. Real Ink/CLI/inert-shell flow previews without
hits, confirms a scoped grant, observes one automatic hit, types `/permissions` and exact-ID
revocation, then refuses the next call. Persisted decision sources identify handler/grant/handler
and correlate tool-use IDs. H6 snapshots add only attribution/correlation fields; existing
event order, tool content and terminal behavior are retained.

Named negative mutations, one bounded independent review, build/typecheck/full tests and
exact-head three-platform CI are delivery gates. Optional polish stays at ROADMAP's end.

Initial build/typecheck/full suite passes 2,271 tests plus two skips across 119 files with four
workers. Two named negative controls failed and were restored: a second policy evaluation
violated the actual-call count, and counting pure `decide()` previews inflated both allow/deny
grant counters. Twenty-eight focused attribution/inspection cases pass after restoration.
Integrated committed main `fba5d50` preserves the independent topic-skill guidance/test update;
the user's separate uncommitted roadmap draft is untouched. Integrated checks are rerunning.
