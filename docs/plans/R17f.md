## What was actually wrong with "just rerun E3"

`eval/live.mjs` is frozen E3 evidence and stays byte-compatible, but it does not measure today's
product. It hardcodes a blanket-allow permission policy, an old `LadderPolicy` with `abort: true`
and both LLM auxiliary capabilities on, an unlabelled memory index string and a 10,000,000-token
guard. It never touches R17b's config resolution or R17d's grants. Rerunning it and calling the
output "today's defaults" would be false.

The newer `runEvaluationAttempt` shares E1/E2 transport, accounting and profile-aware supervision,
but as it stood it also blanket-allowed every call, declared no shell operation descriptor,
observed no file changes, and graded every attempt with an extra advisory model call.

## The measured surface

`eval/r17f.mjs` is the R17f runner. It adds no evaluator framework: preparation, isolation,
independent checks, accounting, reporting and publication are the existing components.

| Reused unchanged | From |
|---|---|
| 96-slot Latin square, Docker argument construction, owned process/container helpers, tree digest | `eval/live-support.mjs` |
| Pinned task set, workspace preparation, independent checker | `eval/tasks.mjs`, `eval/workspace.mjs`, `eval/check.mjs` |
| Balanced-subset summary with visible not-run slots; evidence publication | `eval/summarize-live.mjs`, `eval/pack-live.mjs` |
| Budget/accounting gate, transport, dependency preparation, frozen-memory snapshot, attempt runner, E2 report | `packages/cli/src/evaluation-*.ts` |
| Permission policy, approval controller, transcript renderers, `/why` fold | `run.ts`, `tui/controller.ts`, `render.ts`, core `guidance.ts` |

`eval/live.mjs` changes only by exporting the pinned identity it already used
(`E3_MODEL = { model: "gpt-5.6-luna", reasoningEffort: "medium" }`), so a rerun cannot drift from
E3's model or reasoning effort. Roles, subscription-only auth and "no API-key fallback" are
unchanged.

### 1. The profile is read, not restated

`measuredProfile` calls the product's own `loadRunConfig(new Command("run"), {}, …)` against an
empty home directory and an untrusted empty cwd — what "a fresh clone with no config" means. It
then refuses to continue if the resolved values are not the R17b recommended ones
(`supervise`, `checkpoints`, `ingestOnEnd`, `notifications: "bell"`, `toolSummaries`), or if
`supervisorReview`/`supervisorAbort` have stopped being opt-in. The resolved profile is written
verbatim into `protocol.json`. No user config, project config, environment override or credential
is read.

The supervisor factor is the documented explicit opt-out (`supervise: false`) of that same
profile; nothing else differs between cells.

### 2. Permissions are the real ones

The policy is `buildPermissionPolicy({})` — `RulePolicy(defaultRules)` with the `ask` fallback,
plus the two `memory_search`/`memory_read` allow rules the product itself adds when memory tools
exist. Each attempt gets a real `PermissionGrantRegistry` bound to its own session, and asks are
answered through the actual `TuiController` under R17d's **frozen preset response policy**:
confirm an offered default scoped grant, otherwise allow once; never allow-all, never a standing
tool answer. The evaluation `bash` tool now declares an honest
`describeShellOperation(command, "/bin/sh")` descriptor, because a tool that declares nothing can
never be offered the R12b argv-prefix grant.

`permissions.json` per attempt records every prompt, whether a scoped grant was offered, the
resulting grants, and the approval controller's own displayed lines. In the fake-provider
end-to-end case three shell calls produce two prompts and one argv-prefix grant: the identical
repeat is covered before it reaches the approval handler.

### 3. R17e's visibility reaches the evidence

Each attempt writes `transcript.txt` built with the same composition headless `run` uses
(`AuxiliaryText`, `AssistantText`, `MemoryContextText`, `RecallText`, `renderChatEvent`), and
`why.json` from core's `GuidanceLog` folded over that session's own events. So a supervisor line
says what it noticed and what applying it did, a recall names its page and claim, the injected
index announces itself, and `/why` is inspectable after the fact. `file.changed` observations are
restored so the drift detector has the same inputs it had in E3.

### 4. The frozen corpus is recovered, not retrained

`eval/r17f-corpus.mjs` extracts E3's frozen memory corpus from the committed evidence archive:
the archive is checked against its published SHA-256, all 48 memory-on copies must agree, every
file must match its index hash, and the resulting tree must digest to
`cd10a022f0114f75726f7d6024324ad92d4646a94d608af0fd2f9113e256b2a1`. It refuses an existing
directory. This spends no training tokens, adds no new ingest or dream, and keeps the retrieval
material identical to E3's. The corpus is re-verified before **every** attempt.

### 5. Budget and stopping

`EvaluationBudget` (R9b) is the gate: at most the authorized **12,000,000 reported tokens**
(STATUS 1324/1353, [outside diagnostics](R17b-outside-diagnostics.md)), an explicit wall-clock
deadline, a 60-second bound on every provider request with no automatic retries, and E3's outer
per-attempt hang guard of five minutes plus ninety seconds. Any provider call that leaves usage
unknown stops further scheduling — stricter than E3's tolerance of three. Nothing silently
retries, nothing is rescheduled on an outcome, and every attempt already collected keeps its
evidence. `results.json` is written in the shape `eval/summarize-live.mjs` already reads, so the
largest completed balanced subset and all not-run slots stay visible.

These are reported-token scheduling caps. An in-flight backend response can overshoot them, and
none of this is a guarantee about remote billing.

## Frozen analysis decisions — 2026-09-09, before spending

### Supervisor treatment: heuristics plus the optional LLM ladder

The operator selects `arm: "heuristics+llm"` for the original 2×2, 96-slot design.
Supervisor-on enables the candidate reviewer/grader rungs explicitly, as original E3 did;
supervisor-off disables supervision. The recorded baseline recommended profile remains
heuristics-only. Current thresholds, permissions, grants and visible interventions apply;
automatic abort/restore stays off. This measures the candidate stack, not an isolated estimate
of the LLM rungs versus heuristics alone. There is no third arm, extra matrix or budget expansion.
If the model-backed rungs are not exercised, their benefit remains unmeasured and they stay opt-in.

Memory-on is the original frozen **index plus retrieval tools** treatment; off has neither.
An automatic-index default decision is conservative product policy, not an isolated estimate
of injection versus explicit retrieval. Training cost is zero; original training overlap remains.

Primary comparisons pair task/repetition with the other factor fixed. Preserve E3's threshold:
at least two additional independent passes, no new regression/scope failures, and at most 25%
increase in either median total reported tokens or median session-plus-observer latency.
Report both other-factor settings and per-task outcomes. Pending prose gates, unknown usage and
inconclusive evidence cannot establish a win. A threshold alone does not prove general utility.

If collection stops, `eval/r17f-summary.mjs` selects the largest fully completed 32-slot prefix
for primary comparisons and retains every partial-block observation separately. Keep the
two-additional-passes minimum even for a smaller prefix; never lower it after results. Zero full
blocks means no comparative evidence. Label a partial rerun explicitly. Without demonstrated
benefit, keep LLM supervision opt-in, heuristics and ingestion on, and automatic injection off.

`session-timing.json` captures model session plus joined observer settlement before checking.
`results.wallMs` uses that duration; separate `orchestration-timing.json` includes preparation,
checking and artifact capture. `progress.jsonl` records every call start/settlement and attempt
phase without request/auth text. Per-inflight-call scheduling headroom is 1,178,000 tokens at
the authorized 12M cap (at most 10% for smaller explicit budgets); it is never billed consumption
or a guarantee against remote overshoot. Submitted answer/test files and diffs are captured
through the isolated worker with explicit bounds and omission receipts, never host symlink reads.

Current pinned checker images include R14d attestations, worker-completion evidence and
FAIL-before-BLOCKED ordering added since E3. The task definitions/behavior checks are not retuned;
the checker image is not falsely described as byte-identical to the original image.

### Assessor, decided before any call

A4 and X4 keep their frozen **human** prose gates. Their automatic outcomes remain **BLOCKED**
unless a separately attributed, authorized assessment is actually supplied; this runner never
writes `humanVerdict`, and E3's 2026-09-06 AI-assessor amendment was explicitly for that
completed run only. Failed, missing or inconclusive evidence cannot establish benefit.

### Controls this surface fixes, honestly

Shell-only task tools plus `update_plan`, and `memory_search`/`memory_read` when memory is on.
Frozen retrieval only: no held-out ingest, dream, online learning or corpus edit. No subagents,
MCP, external memory backend or compaction. This minimal evaluator does not install post-edit
diagnostic, checkpoint or session-end ingestion hooks; those recommended settings are recorded
but not exercised. **This is not an
interactive usability comparison.** Nothing here measures TUI rendering, prompt history,
notifications, or `/why` as a person would use it; a shell-only worker cannot.

E3's collection limitations still apply, including the X4 training-description overlap and the
A4 output-contract ambiguity. The evaluation is small, public, synthetic and three-times
repeated; it cannot establish general superiority.

## Running it

```sh
pnpm build
docker build --target worker -t agentrig-r17f-worker -f eval/Dockerfile eval
docker build --target checker -t agentrig-r17f-checker -f eval/Dockerfile eval
docker image inspect agentrig-r17f-worker agentrig-r17f-checker --format '{{.Id}}'
node eval/r17f-corpus.mjs /absolute/new-frozen-corpus
node eval/r17f.mjs /absolute/settings.json
node eval/r17f-summary.mjs /absolute/new-evidence-directory
```

A1–A4 need a worker image carrying matching offline dependencies for the pinned AgentRig
revision under `/opt/agentrig-eval-deps` ([R9b](R9b.md)); with `"dependencies": "offline-image"`
nothing in the run reaches the network. `"network-prepare"` is the declared E3-compatible
fallback: only dependency preparation gets a network, never the model session, and the choice is
recorded in `protocol.json`.

```json
{
  "worker": "sha256:REPLACE_WITH_WORKER_IMAGE_ID",
  "checker": "sha256:REPLACE_WITH_CHECKER_IMAGE_ID",
  "source": "/absolute/pinned-is-number-source",
  "memoryCorpus": "/absolute/new-frozen-corpus",
  "output": "/absolute/new-evidence-directory",
  "arm": "heuristics+llm",
  "dependencies": "offline-image",
  "rounds": 3,
  "maxMinutes": 720,
  "totalTokens": 12000000
}
```

`rounds` selects balanced blocks of 32 in the frozen order (1, 2 or 3 → 32, 64 or 96 attempts).
The output directory must not exist; the evaluator must be committed and clean; images must be
present locally and pinned by ID, and none is pulled. The safe network-free smoke is
`pnpm exec vitest run packages/cli/test/r17f-evaluation.test.ts`, which runs all four
configurations end to end on a scripted provider with the real checker.

## Changes to shared code

`packages/cli/src/evaluation-attempt.ts` gains deliberate seams, all default-preserving for the
existing `evaluate` path: optional `permissions`/`permissionGrants`/`onAsk`, optional
`fileChanges`, `hangGuardMs`, `advisory` and `observe`, and an always-declared shell `operation`
descriptor (inert under a blanket-allow policy). One behaviour change is not merely optional:
supervisor ladder auxiliary usage is now paired with its `auxiliary.usage` ids and written into
`auxiliary.json`, instead of being dropped. When the counts do not match, the snapshots stay
empty and the mismatch is recorded rather than guessed.

## Proposed default control, if the results call for it

Automatic index injection and explicit retrieval share one gate today: `agent-builder.ts` builds
`memoryIndex` and `memoryTools` from the same `opts.memory`. Turning injection off therefore
needs one new config key (for example `memoryIndexInjection`, default decided by the result)
read only where `memoryIndex` is assigned. Session-end ingest (`ingestOnEnd`) and the
`memory_search`/`memory_read` tools keep their current behaviour and are not touched. The
supervisor side needs no new key at all: `supervisorReview` and `supervisorAbort` are already
opt-in, so "LLM ladder defaults off" is the current state and would simply be documented as
measured rather than assumed. **No security default moves either way.**
