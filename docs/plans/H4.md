# H4 — Runtime-backed, claim-level promotion eligibility

## Boundary

Page-written citations and confidence are untrusted proposals, not evidence. Load a bounded
snapshot of regular session-log files supplied by the trusted raw store; validate session IDs,
sequence numbers, lineage and source locations. Do not resolve filesystem paths from citations.
Raw logs remain append-only inputs; this is not protection against a host actor rewriting them.

Keep the existing synchronous selector, but require an opaque runtime-loaded evidence index.
Without it selection fails closed. Evaluate each distinct tagged claim separately, grouping
repeated identical claim lines to combine their citations. Every claim needs the configured
minimum (at least two) independent witnesses. Frontmatter source counts cannot fill claim gaps.

The initial support rule is deliberately conservative: the claim must match a complete textual
line in a recorded tool result (with numbered read_file prefixes accounted for). Assistant text,
requests, patches, incomplete outputs and unrelated records cannot establish support. Paraphrases
without this checkable support are rejected, not upgraded by model confidence. Exact textual
support is structural eligibility, not proof of semantic truth; every proposal requires human
review with source session, event, field, character range, hash and excerpt displayed.

Claims present in recorded tool inputs in the session or inherited ancestry are rejected as
potentially self-authored, including shell echoes and write-then-read sequences. Receipt tools,
memory views and delegated/skill text are not observations. Legacy display truncation markers
without full output are also excluded. These are conservative guards, not a complete authorship
proof: cross-session writes outside recorded lineage and encoded/assembled agent-authored text
can evade the input check. Human review must assess source independence and semantic support.

Related fork/subagent lineages count as one source family. Identical normalized result payloads
count as copies of one observation even across unrelated session IDs. This errs on the side of
rejecting ambiguous independence. Validate fork points and parent existence; cycles, missing or
corrupt lineage, unreadable/symlinked logs and resource-limit exhaustion fail closed.

## Integration

- Dream validates the final, post-consolidation pages against runtime evidence, never the old
  pages that may have been merged away. It only proposes promotion; it does not write global memory.
- The explicit CLI promotion command uses the same gate before invoking the backend transport.
  It previews by default; `--confirm` rechecks before publishing. Unsupported prose cannot ride
  along with a supported fact, and the publication artifact contains only checked claim lines and
  supporting session references, not unverified extra citations. The local page is untouched.
- Reports separate structural witness checks from unassessed semantic truth and retain rejection
  reasons. Backend adapters remain low-level trusted transport APIs, not evidence validators.

## Verification

Reject fabricated IDs, unrelated real sessions, citations supporting different claims, assistant
echoes, incomplete results, copied observations, forked copies, bad locations/lineage and pages
with unsupported prose. Accept separate supporting observations with distinct contexts, retaining
auditable locations/excerpts. Test dream final-page selection and CLI gating, then build/typecheck,
full suite, independent review and PR/main CI before H5.
