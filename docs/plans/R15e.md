# R15e — on-demand diff review

Starts from green R9c main `3b7564a`; R9c PR183 passed all four exact post-main
checks (CI34047589688 and scripted workflow34047589697). R15e is independent of
ACP and is pulled forward while R15a waits for that dependency. This does not
partially deliver R15a, R15c or R15f.

## Contract before implementation

- Extend the existing supervisor reviewer with an explicit diff mode using its
  existing AuxiliaryRun. Do not manufacture an agent trajectory or introduce a
  second review engine. Findings are advisory, not test evidence or approval.
- CLI `review` captures tracked HEAD-to-worktree changes; untracked files are
  explicitly excluded. `--base <ref>` reviews resolved commit-to-HEAD changes.
  `--pr <positive-number>` reads GitHub metadata and patch through fixed `gh`
  argv. No checkout, source fetch, tests, edits or automatic comments.
- Text diff limit **16 KiB**, **40 files**, **128 hunks**, **16 findings**.
  Findings have a validated changed-file/old-or-new hunk line, severity and bounded
  text. Response limit **32 KiB**, **4096 model events**, one model call with
  requested maximum **2048 output tokens**, existing **30 s call /90 s total**
  auxiliary deadlines. Smaller supported time/per-response limits win. Effective
  total-session `maxTokens`/`maxUsd` settings explicitly refuse before provider
  construction in both CLI and TUI; select a review profile using supported bounds.
  No total-session cap is silently discarded or claimed enforced. Missing usage
  stays unknown; requested tokens are not a hard remote billing cap.
- Git/gh subprocesses have **15 s** each within **90 s** operation lifetime,
  **64 KiB** bounded output (patch separately16KiB; metadata16KiB), joined owned
  cancellation. No shell, diff drivers, textconv, hooks, automatic network or
  model-generated argv. Unsupported/binary/oversized diff refuses before model;
  an empty diff makes zero calls. Diagnostics do not echo raw subprocess errors.
- Capture HEAD and exact patch identity; compare again after review before
  presenting findings. Resolve refs as commits with option-safe argument handling.
  PR metadata binds repository, base and head; recheck before an explicit comment.
  This is point-in-time observation, not atomic remote compare-and-post.
- Every gh read/write requires configured exec and net decisions; headless ask
  denies, TUI uses its current asker/registry. `--comment` requires `--pr`; no
  invalid, cancelled or incomplete-usage review is posted. Enforcing sandboxes
  refuse host git/gh, including YOLO, rather than quietly bypass containment.
- Idle TUI `/review` delegates to the same operation, reserves its command name,
  joins cancellation/shutdown, reports separate auxiliary usage and refuses while
  agent/maintenance work is active. No fabricated session or after-terminal event.
- Tests use actual local Git and local/fake provider, fixed fake gh transport;
  never live comments/model spend. Actual CLI and TUI frames, policy denial,
  malformed location/output, identity change, caps, cancellation and nonexecution
  controls precede full build/typecheck/test, named restored mutants and one
  bounded independent review. Exact-head all-four CI and root-only merge follow.

## Explicit limits

The diff is context, not proof that a claim is correct. No project source beyond
the captured patch is implicitly loaded. Local commands run trusted installed
Git/gh binaries; bounds do not sandbox hostile executable code. Concurrent writers
can change files again after the final observation. Cancelled remote model work
may keep running and its usage can remain unknown. No automatic retry or posting
is inferred from model text. Optional polish belongs at the roadmap's end.

GitHub CLI primary interfaces checked: [PR diff](https://cli.github.com/manual/gh_pr_diff),
[PR metadata](https://cli.github.com/manual/gh_pr_view), and
[comment stdin](https://cli.github.com/manual/gh_pr_comment). No `--web`, editor,
attachment, replace or delete flags are used.
