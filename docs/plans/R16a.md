# R16a — bounded final-answer Markdown presentation

## Contract before implementation

New branch from updated four-check-green main `749ff26` (R15c #193; CI
`34061897223`, structure `34061897204`). R15's first interaction group is delivered.
R16a is independent of R16c's controller-side tool summaries and remaining provider
and role work; each retains its own branch/PR and integrated-main gates.

Render completed assistant replies as Markdown-to-ANSI immediately before the
existing Ink Static presentation. Headings, emphasis, lists, blockquotes, tables
and fenced code with common-language highlighting; plain paragraphs stay readable.
Use the existing completed `AssistantText` lifecycle, including partial replies
flushed on cancellation. No additional model call, permission, event or log rewrite.
Controller lines remain original text for ACP/other consumers. Non-assistant lines,
questions, permission effects and thinking markers do not acquire Markdown semantics.

Keep streaming as literal text through existing `fitToRows`/`liveRows`. No parsing
every token or repaint of old Static lines. Cache a completed line's presentation
for its first rendered width/color mode; a later resize does not rewrite old terminal
scrollback. Width-dependent table fitting belongs in `viewport.ts`; no external
word-wrapping renderer or relocation of the live-frame height budget. No alternate
screen, panes, mouse or scrollback rewrite.

## Parsing, terminal safety and bounds

Use pinned maintained parsers: `marked@18.0.11` lexer tokens and `lowlight@3.3.0`
syntax trees. No HTML generation/execution, DOM, URL fetch, automatic language
detection, dynamic plugin/grammar loading or OSC hyperlinks. Register only a fixed
common-language subset; unsupported languages remain literal code. Renderer-owned
fixed SGR sequences are the only control sequences it emits. Text atoms are sanitized
after parsing/decoding as well as before parsing, preserving ordinary indentation and
newlines while removing terminal controls and bidi formatting. Literal HTML remains
text, not instructions. Links/images show bounded labels/destinations, never load them.

Bound added formatting work: lex at most 32 KiB source, render at most 4096 tree nodes/depth 16,
code highlighting at most 8 KiB per fence, output at most 128 KiB. Oversized source,
formatting failure falls back to bounded literal text
with an explicit formatting/omission notice. Table layout bounds 16 columns,
100 rows and bounded cell widths; excess receives an explicit omission marker.
These bound added presentation state, not total core history or a hard CPU/RSS quota
for third-party parsing. No silent truncation of stored/model-visible content.

Honor `NO_COLOR` for added formatting and expose deterministic color selection to
tests. This is not R16h's theme/keybinding system. Keep all styles cosmetic: they do
not confer authority, represent verification or change runtime permission decisions.
