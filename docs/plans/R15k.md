# R15k — explicit TUI file and clipboard-image attachments

## Contract before implementation

One bounded roadmap row, new branch from green main `93452df` (R16d #200).
Root approved the prepared contract; implementation and all gates remain pending.
No real clipboard, provider, credentials or OS image generation in validation.

Interactive ordinary prompt submission recognizes bounded explicit `@path` references
(quoted paths for spaces, `@@` for literal at-signs). Slash commands, permission,
question and escalation answers are not attachment interpreters. File references
are read-class operations; neither names nor extensions authorize reads. Tab offers
single-directory bounded metadata completion only after read authorization, never
exec permission or inferred model consent. Completion insertion is not payload read.

Actual materialization occurs through the core's permission/grant/sandbox tool
pipeline, using trusted internal tools never advertised to the model. All reads
must succeed before the first provider dispatch. An explicit user clipboard gesture
may stage a PNG; no startup reads, polling, automatic paste inspection or OSC52.
Unsupported host clipboard access in enforcing sandboxes refuses. Helper executables
are trusted host code, not sandboxed merely by receiving fixed argv.

Only remaining explicit prompt prose is fresh user instruction. File blocks use
R13b before/after canonical source labeling (project inside trusted root, otherwise
external), always advisory. Explicit clipboard images are user-sourced advisory
data, not instruction/grant authority. Attachment-only initial/continued/resumed
input cannot clear R13c by manufacturing placeholder prose. Canonical events and
snapshots preserve actual image/text data and provenance. They are sensitive and
may later be ingested; input history and screen chips exclude materialized bytes.

Bounds: eight attachments, text 64 KiB each/256 KiB aggregate, image 4 MiB each/
8 MiB aggregate, 16 million declared pixels; filenames 4096 characters. Text must
be valid UTF-8. PNG/JPEG/GIF/WebP file headers are validated without pretending to
fully decode/attest image contents; clipboard output must be PNG. Nonregular,
unsupported, malformed or oversized inputs refuse without partial model dispatch.
Completion inspects at most 256 entries, shows at most 32 candidates and never
recurses or reads file contents. No wildcard expansion or arbitrary shell strings.

Clipboard helpers: `wl-paste --type image/png --no-newline`, local-display X11
`xclip -selection clipboard -t image/png -o`, macOS `pngpaste -`, or Windows
PowerShell with fixed noninteractive/no-profile STA script calling Clipboard.GetImage
and encoding PNG to stdout. Pick one backend; no cross-clipboard fallback. Two-second
timeout, bounded stdout/stderr, cancellation and joined owned child termination.
These bounds do not cap native decoder memory before capture. Missing helpers and
unavailable clipboard visibly refuse; `@image.png` remains the portable fallback.
