## Evidence and limits

The first sustained workload was the 2026-09-19..21 drain:
`~/.agentrig/trains/drain/logs/drain.log` records 30 DONE row outcomes (including
one operator reclassification) and 18 HALTED attempts, not 48 distinct shipped
rows. The [current checkpoint](../ROADMAP.md#current-checkpoint--r17a-dogfood-evidence-2026-09-19-to-2026-09-21)
retains counting limits, operator involvement and separate follow-up receipts.
The dominant costs were not missing capabilities: bookkeeping halts over receipts,
canonical headings, residual metadata, merge sequencing and reopened blockers
required operator-written resume rows and fresh conductor re-clones, rebuilds and
re-orientation. Concurrent load on one provider login exposed fatal mid-reply child
disconnects (#467) and fetch failures in two conductors. Prose-pattern review gates
had false positives (#424, #425, #456, #459). The
[#320 replay trial](https://github.com/agentkitai/agentrig/issues/320) had both
row-115 replay arms deadlock while review tooling reviewed itself using its own
adapters. These observations motivate R18; they do not establish runtime success.

## Renunciation and safety

No new capability: every row makes existing unattended shipping cheaper, more
resumable or more verifiable. Security defaults do not widen authority. Persisted
state and recovery must preserve scoped task/merge authorization, explicit denies,
sandbox boundaries and project trust; neither a queue row nor a retry invents
approval. Independent review, exact-head CI and serialized merges with green
post-merge CI remain gates. LOW own-wording observations are advisories, not new
residual issues. No nested milestone expansion or unrelated product work.

## R18b implementation

Implementation complete; independent review and landing pending. Core resumes modern
message logs ahead of snapshot caches, including no-snapshot crashes, and restores plan
and child observations as advisory data. CLI accepts taskless `run --resume`; ship/topic
define each phase continuation, ledger/head reconciliation, and no duplicate builder or
repair-budget charge for an already recorded failed child. Missing child termination is
unresolved until logs/handoff are reconciled, never inferred success. PR ledger remains
workflow evidence rather than an executable decision engine in core. Tests distinguish
log/CLI guarantees from skill instruction contracts; fake providers are deterministic,
not a claim that arbitrary models will follow instructions.

## R18c implementation

Implementation: `agentrig train <dir>` is a thin CLI over core's exported queue
transport (`TrainRowSchema`, `runTrain`). Core owns process/filesystem execution
infrastructure; the supervisor remains a type-only event observer. The transport
calls the existing headless run path and checks GitHub landing evidence; it does
not make review, repair, consent or merge decisions. Those stay in ship/topic.

Rows have strict task/authorization/scope/environment input and optional same-session
resume/PR pointers. Queue/active/done/halted/logs, one-drain locking, STOP/PAUSE,
per-row checkout rebuild checks, conservative one-time infrastructure retries and
exact-merge-commit required CI are documented in TRAIN-OPERATIONS. Non-landed rows
halt with machine-readable phase/PR/head/session evidence. Fixture/fake-command
tests cover schema refusal, landing/CI gates, between-row checkout, retry bounds,
resume, interruption and operator controls; a built CLI STOP fixture proves routing.
These are deterministic transport proofs, not the 30-row live band acceptance.
Independent review and exact-head CI remain pending at builder handoff.

Repair round 1 encodes the row/authorization as JSON and uses host-owned validated
final-output capture from `run --json`, not model writes outside the checkout. New
PRs require a fresh host row marker and a merge not already in the starting base;
only an exact operator-pinned PR resume is exempt from marker/newness checks. All
PRs require freshly fetched reachable base ancestry, failing closed on fetch or
object errors. Unexpected queue extensions are errors, and unique atomic temporary
files keep stale write remnants from blocking recovery halt evidence. Targeted
regressions cover repository root, base branch, origin, fetch, fast-forward and
locally advanced base refusals, plus these repair behaviors. Repair round 3 adds
specific regressions for a train directory inside the checkout, stale result
receipts, a receipt changing the operator-pinned resume PR, and reuse of done or
halted row identities. These are fixture-level guard proofs, not live-train evidence.

### R18d implementation contract

`review-verdict.mjs` is the versioned zod wire contract. One delimited JSON block
binds reviewedHead, assertedModel/modelSource, slot, verdict and findings (severity,
verbatim heading, file:line, blocking flag, scenario). Prose is preserved but is not
machine authority; invalid structured blocks never fall back. Historical block-free
prose is a logged nonfatal index/display fallback only, not landing proof.
Base-pinned adapter/skill instructions keep tooling-changing PRs from reviewing
with their own copies. Completion-marker timing has one canonical definition in
SHIPPING-WORKFLOW; the land marker gate remains unchanged. Builder leaves ROADMAP
untouched. #473 and #487 regression fixtures accompany R18d, not R18c/e behavior.

## R18e implementation

Row usage joins append-only call admissions/settlements, then traverses session
spawn ancestry from persisted train state. Queue status (`train --status` and
normal status emission) and `usage --row <id> --train-dir <dir>` expose per-row,
per-session, provider/model totals, raw tokens, incomplete calls and priced-subset
coverage. Historical configured rates are retained; ChatGPT-login calls are
explicitly unpriced, including when API pricing flags are present. No completion
marker is set here; conductor review/landing gates remain outstanding.

Multiply claimed sessions and their descendants are excluded from every claiming
row with explicit coverage diagnostics; unrelated row totals remain available.
Live torn spawn-log tails use the valid prefix, while missing/unreadable logs warn
only affected rows. Session coverage gaps remain row-scoped; only sessionless
ledger diagnostics are labelled ledger-wide, confined to their checkout.

Named provider entries optionally bound concurrent streams via cross-process
filesystem slots shared by the same OS user. Waiting emits `model.wait`, is
abortable, and does not block other entries. See [spend-ledger operational
contract](../SPEND-LEDGER.md#train-rows-and-provider-entry-concurrency-r18e), including
orphan-slot reconciliation and retained ledger/session-root requirements.

Issue #479 remains open: provider concurrency does not serialize local declared
checks. The train's existing single infrastructure retry recognizes transport
failures, not Vitest's 5000 ms single-file timeouts (and rejects FAIL/assertion
output). Neither mechanism implements the requested isolated file re-run or a
spawn-heavy test budget. Closing that issue on the strength of R18e would be
incorrect; this row does not silently widen infrastructure retry classification.
