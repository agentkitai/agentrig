# R12e — Semantic authorization boundary

Explicit narrow shell authority binds to literal argv, never a substring, a tool's suggestive
name, model/transcript prose, or an MCP read-only hint. This row adds an exercised runtime
boundary without implementing R12a's grant records, duration, revocation or inheritance UI.

## Contract

- `--allow-command '["git","status"]'` (repeatable), or config
  `"allowCommand": [["git", "status"]]`, explicitly authorizes foreground built-in `bash`
  operations whose parsed argv starts with those exact elements. `git status --short` matches;
  `echo git status`, `git statusx`, `git status; printf changed` and `git $(printf status)` do not.
  Entries are not glob patterns. Existing `--allow 'git *'` remains a literal tool-name rule;
  it is not reinterpreted as shell authority.
- Built-in bash derives `PermissionRequest.operation` from the final schema-validated input
  after ordinary pre-tool hooks and from its configured resolved shell, not a model-supplied
  descriptor. Existing invalid-hook-patch handling keeps the original validated input. The
  descriptor is persisted in permission events and displayed by verbose CLI and ask prompts.
- Only `sh`, `bash` and `dash` executable basenames (including Windows Git Bash `.exe`) use the
  bounded POSIX literal lexer. Unknown shells, cmd and PowerShell are unsupported. Commands
  are at most 16 KiB, 128 argv elements and 4,096 characters per element. Prefixes have the same
  element limits and 16 KiB serialized size; CLI/config accept at most 128 prefixes.
- Unquoted expansions, shell operators, redirections, globbing, escapes, comments, control
  constructs, leading assignments, unmatched quotes and control characters cannot satisfy a
  narrow scope. Single quotes preserve literal metacharacters. Double quotes accept literals
  but reject expansion and escaping. Concatenated literal quote fragments and ordinary tabs
  between words are supported. This intentionally rejects some harmless syntax.
- Missing/unsupported descriptors and background commands cannot satisfy a narrow rule;
  with no other explicit authority they ask (and unattended ask denies). An independent
  explicit `--allow bash`, `--allow exec`, `--yolo`, or remembered TUI all-session answer retains
  its existing blanket authority. CLI deny rules precede both narrow and broad allows.
- The SDK's optional `Tool.operation` callback is trusted host code, like its permission/path
  callbacks. MCP metadata and model input cannot install it. MCP definition consent remains
  independent: neither an argv rule nor blanket permissions bypass R5d consent.

## Honest limits

This parses shell syntax, not program effects. A prefix does not attest the executable, PATH,
working tree, aliases, shell startup environment, Git hooks/config, wrappers, or read-only
behavior. Explicitly granting `["git"]` is broad Git authority; flags and program sublanguages
may execute further code. Grant only a prefix whose entire accepted suffix space is intended.
The existing sandbox remains an independent containment boundary; an allow never relaxes it.
Trusted SDK callbacks and explicit blanket grants are not inferred permission.

R12a–R12d retain the committed grant lifecycle and richer effect/UI work. Optional additional
shell dialects are not a prerequisite or a new nested milestone.

## Evidence

Parser/matcher tests cover positive argv, injection operators, substitutions, quote/escape
distinctions, prefix bounds, unknown dialects, names/prose/hints, missing descriptors and
background requests. CLI config/Commander tests exercise the shipped option. A fake model drives
the real agent/built-in shell with literal metacharacters; an inert real-shell control proves
that the rejected command-substitution variant actually expands. Runtime tests reject forged
input descriptors and changed hook commands, and allow literal `git status`. Exact-head build,
typecheck, full suite, mutation, independent review and three-platform CI receipts follow below.
