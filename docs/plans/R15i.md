# R15i — bounded project spend ledger

Approved implementation contract, 2026-09-07. Base: delivered R15h main
`31193d649880ade62d6b8ca1ec0525318727ea76`. This row adds configured-estimate
accounting and admission, not billing guarantees or a generic accounting engine.

## Operator contract

- `--daily-cap <usd>` / config `dailyCap` accepts finite positive USD up to
  1,000,000. Convert to safe integer micro-USD, rounding caps down and reservations
  up. Reject unsafe arithmetic and a positive cap rounded to zero.
- Reuse explicit input/output/cache pricing and the existing disjoint usage/cost
  helpers. Freeze resolved rates on each new call; never reprice historical tokens.
- Record by default only inside an established trusted project. Capped execution
  refuses without that boundary. A new ledger does not establish earlier spending.
- R7 execution stays explicit opt-in. This is a configured model-cost admission
  limit, not an invoice bound or a limit on shell, MCP, services, or arbitrary host
  JavaScript expenditure.

## Metering and reservation

One wrapper at existing provider construction meters main, child/grandchild,
compaction, memory, reviewer/grader and lazy entry calls. Reused providers are not
wrapped twice. Worktree children retain the parent's trusted ledger root. Existing
auxiliary snapshots are not charged again.

Capped CLI execution supports built-in Anthropic and OpenAI adapters at canonical
service endpoints with requested output limits. Require explicit input/output
pricing and finite configured context/output bounds. Refuse ChatGPT (its backend
ignores the output cap), custom endpoints/providers without a trusted bounded
contract, and known unmetered auxiliary model paths before dispatch. Disable
automatic provider retries in capped mode: uncertain attempts are not free.

Reserve the configured full context window at the highest resolved input/cache
rate plus requested maximum output at the output rate. This is an explicitly
configured envelope, not tokenizer/server attestation. Actual reported overrun
remains recorded and blocks later admission; never silently cap recorded cost.

## Durable records and concurrency

Fixed `.agentrig/usage.jsonl`, no model-selectable path. Unique run-segment and call
IDs correlate admission, settlement and session-end records. Per-call usage uses
the final cumulative snapshot once, with disjoint cache categories. Resume/fork
records only new calls, not inherited snapshot totals. Records contain bounded
IDs/model/time/usage/frozen rates/coverage, never prompts, output, credentials or
arbitrary error prose.

Bounds: 16 MiB file, 100,000 records, 8 KiB per record, 32 outstanding calls.
Malformed, unsafe, overflow or unavailable ledger refuses capped admission; no
automatic pruning. Reuse canonical path checks and a bounded cooperative lock.
Under lock, check settled estimates plus outstanding reservations, append and
sync admission, then release the lock before dispatch. Never dispatch first.

Each call belongs to its admission UTC day. Concurrent processes cannot admit the
same remaining allowance. Missing final usage, retry uncertainty, abort, crash or
failed settlement leaves an unresolved reservation and blocks further capped
calls across midnight as well. No age-based expiry, lock stealing, automatic
replay, or silent reset. A write failure after dispatch is visible uncertainty;
cancellation of owned work does not prove remote billing stopped.

Recovery documentation requires stopping cooperating writers and preserving all
audit evidence for reconciliation. There is no recovery command in this row and
no promise that deleting a lock, record or ledger safely restores an allowance.

## Surfaces and boundaries

- `/cost`: current run segment plus today's recorded project estimate,
  reservations, unknown coverage and coverage start.
- `agentrig usage --since YYYY-MM-DD [--json]`: bounded read-only report, no model
  initialization, credential reads or secret configuration output.
- `budget.cap`: fixed-reason startup/per-call refusal or exhaustion event. Session
  logs remain append-only with no events after their terminal event.
- Existing source trust, permission, scheduled provenance, role limits and
  auxiliary lifecycle semantics remain unchanged. No invoice lookup/live pricing,
  subscriptions, daemon, account-wide quota, or automatic unattended enablement.

## Implementation record

Contract recorded before source edits. Implementation controls include actual
canonical-provider CLI startup/refusal, controller `/cost`, scheduler receipts,
SDK child/compaction/session-end maintenance, resume segments and cross-process
last-slot contention. CLI native-provider validation runs before decoration.

The first full Docker pass found ten failures (2,933 passed, two existing skips).
Eight existing injected-provider fixtures bypass the construction hook. Hard
refusal now applies only to capped execution; an uncapped unmetered SDK run keeps
ordinary behavior and first records a durable unknown-coverage gap. A later capped
run cannot call that gap zero spend. Existing behavior assertions remain intact.
Two heartbeat artifact assertions are deliberately updated for usage.jsonl as
operational accounting, retaining one request and no task/wiki/report effects.

Outstanding reservations from another process conservatively block admission even
if that process is alive and allowance remains. This is stricter than summing all
live process reservations; only this ledger object's live calls may overlap under
the 32-call bound. No PID/heartbeat/liveness framework is introduced. An uncapped
ledger I/O failure emits explicit unknown-coverage warnings and preserves ordinary
execution, attempting a durable gap only when possible. It never claims a durable
receipt if that write fails. Capped unavailable accounting refuses dispatch.

Build/typecheck and full digest-pinned Docker passed: 2,961 tests, two existing
skips, 184 files, 59.90 seconds. Available token snapshots were then added to the
same bounded report; cache-disjoint totals have a focused assertion. One final
full run and exact-head CI remain after the single review.

Four named source mutations each produced the expected assertion failure and
were restored immediately: `bypass-remaining-allowance` (second SDK run incorrectly
done), `clear-unknown-at-midnight` (unknown prior call incorrectly admitted),
`sum-cumulative-snapshots` (22 versus 20 micro-USD), and
`allow-unmetered-capped-sdk` (missing required construction refusal). Restored
focused tests pass; these are behavior controls, not compilation failures.

The live byte-prefix guard is bounded to the active object and does not claim
cross-restart tamper protection. Accounting uses fixed endpoint/configured-envelope
assumptions; canonical session admission failures emit budget.cap, while invalid
provider/cap configuration refuses before a session exists and reports a CLI error.
