# R16d — bounded interactive history and completion

Approved contract, 2026-09-07. This independent row starts from green main
`31193d649880ade62d6b8ca1ec0525318727ea76` while R8d PR #197 awaits its own
updated-main integration. ROADMAP §5 explicitly permits R16a/c/d in parallel;
this does not skip dependent work or add a milestone hierarchy. R8d stays frozen

this row owns the composer, preserving their output seams on integration.

## Contract before implementation

- Interactive TUI only. Up/Down recall prior composer submissions and restore the
  unsent draft. Editing detaches recall; recall never submits. Tab at an initial
  `/token` completes current built-in and loaded skill names, case-insensitive,
  deterministic, with built-in precedence. Longest common prefix then a bounded
  candidate hint; no argument/path completion or execution/loading side effects.
- Shift-Enter inserts LF when the terminal distinguishes it. Portable Enter after
  an odd trailing backslash removes one slash and inserts LF; an even run submits
  literally. Pasted content remains literal, with both normal Ink input and bytes
  adjacent to bracketed-paste markers handled consistently. Existing quiet-point
  dispatch and viewport wrapping remain authoritative.
- Permission, question and supervisor-escalation input never recalls, completes or
  enters history. Blank inputs and drafts are not saved. Normal explicitly
  submitted composer lines, including slash invocations, may contain secrets:
  history is sensitive local text, not encrypted or a source of authority.
- After normal startup establishes `trustedProjectRoot`, persist in canonical
  project `.agentrig/history`; otherwise keep memory-only history. Headless,
  ACP/MCP/web controllers never initialize this store. No new trust consent or
  config option, no global history, and no automatic project ignore/index edits.
- Versioned JSON, 200 entries, 16 KiB UTF-8 per entry, 256 KiB serialized file.
  Consecutive duplicates collapse; newest entries survive capacity eviction.
  Oversized prompts still submit normally but are not saved, with a fixed notice.
  Never truncate text mid-codepoint. Bounded read and strict validation; malformed,
  oversized, symlink or nonregular files refuse without overwrite.
- Atomic same-directory temp replacement under a bounded cooperative lock. Reuse
  the smallest suitable existing helper where available. Owner-only newly created
  files; no target unlink, force replacement or stale-lock stealing. One active
  persistence operation with a bounded pending batch; join on UI shutdown.
  Failure disables persistence for this UI and emits a fixed content-free notice,
  without changing task decisions. Cooperating processes merge under the lock.
  These are trusted-host filesystem checks, not isolation from hostile racing code.
- History is outside immutable raw sources; no history event or model injection.
  Exclusion means the history file is not ingested, not that a genuinely submitted
  prompt disappears from canonical session evidence. No change to normal ingest.

## Required evidence

Real Ink/startTui restart and fake-provider dispatch tests: multiline recall,
draft restoration, completion/no execution and built-in/skill collision, both input
paths, unchanged paste/coalescing/frame bounds, and sensitive-answer absence.
Storage caps, malformed/link refusal, concurrent writers and shutdown settlement.
Actual ingest with a history-only canary absent from provider input/wiki while
logged submitted text remains inspectable. Named mutations must fail and be
restored. One bounded Claude review with original findings and material fixes;
build/typecheck/Docker full and exact-head Linux/macOS/Windows plus structure CI.
Root serializes merges after updated-main gates. No live provider calls.

Non-goals: editor/fuzzy search, configurable keymap/theme, render redesign, generic
history framework, new dependencies, permission or session-log changes.

## Implementation and verification checkpoints

Reuses exported `withMemoryLock`, not a new locking framework: 500ms acquisition
window, no reentrancy bypass or stale-age stealing, owner identity checked on
release. In-flight filesystem operations are joined, not hard-time-limited.
One active writer and a pending batch each obey entry/serialized-byte bounds;
oldest pending history may be evicted just like oldest retained history. Release
failure disables subsequent persistence but never claims an already committed
write was undone. Existing project files are not chmod-ed or rewritten on load.

Tab completion uses up to 256 validated catalogue names and eight displayed names
in the existing one-row status slot. It does not add frame rows. Only a single
initial slash-name token completes. Distinguishable Shift-Enter supports the
existing Ink shift flag and CSI `13;2u` / `27;2;13~` forms; no terminal mode is
enabled and the trailing-backslash fallback works without enhanced key protocols.

Initial author checks: build/typecheck and 70 focused checks pass, including real
Ink and production startTui with fake terminal IO/provider, trusted/untrusted
restart, and actual ingest. The first fresh-worktree typecheck before building
could not resolve workspace dist declarations; build then typecheck passed.
Early test-only corrections fixed a malformed test declaration, an imported
EventEmitter in a hoisted mock, and expectations using `ended` rather than the
controller's actual settled `idle` state. Ingest's fake summary now reflects only
canaries actually supplied to the provider, rather than expecting a generic
summary to reproduce the prompt. These were author fixture errors, not hidden
production failures.

Named mutations detected and restored before review:

- Remove composer `history.remember`: both production-startup controls fail empty
  history versus the submitted exact multiline prompt. Repeated with mutant held
  through process completion after an initial run restored too early.
- Remove protected-input recall guard: both actual keyboard paths fail the human
  question answer (`OLD_PRIVATE_PROMPTANSWER_CANARY` versus `ANSWER_CANARY`).
- Remove retention trimming: actual file has 221 versus 200 entries and 655,415
  versus 262,144 maximum serialized bytes. Restored code retains newest entries.
