## Contract

- `/clear` is the existing `/new` operation with identical busy checks and grant
  reset; same trusted configuration, no model call.
- `/doctor` runs the existing plain diagnostic with `probe: false`, bounded
  terminal-safe output, no model or credential refresh. It reports configuration,
  not live provider availability. Existing filesystem probes are cooperative and
  cannot be forcibly cancelled; no hidden background repeat/probe is introduced.
- `/diff [checkpoint [turn]]` captures tracked worktree changes against HEAD or a
  validated checkpoint belonging to the selected session. Reuse protected Git
  subprocess execution, filter refusal, canonical root checks, permission checks,
  cancellation, identity recheck and output limits from local diff review. No
  reviewer, GitHub calls, external diff/textconv/filter execution or provider.
  Untracked/binary coverage is explicit; this is not an undo or ownership claim.
- `/compact` is an explicit owned core maintenance operation, not an empty normal
  user turn. It accepts a finished persisted conversation and uses existing
  compaction/provenance, store locks, session forks and lifecycle primitives.
  No ordinary model loop, tool dispatch, user-prompt/session-end hooks, supervisor,
  final-output repair, memory ingest or dream is launched.
- Compaction operates on an explicit child fork. The original selected session,
  raw log and snapshot remain unchanged until a completed child has a validated
  canonical compaction receipt, atomic snapshot and terminal event. The controller
  adopts only after successful verification and grant reset. Failure/veto/no-op
  keeps the original selected. Partial children remain unadopted diagnostic
  artifacts, never silently deleted or advertised as completed maintenance.
  This does not claim atomicity across a JSONL append and snapshot rename.
- Preserve the verified parent task, usage, roles/provenance and retained opaque
  reasoning/tool pairs. Summaries remain advisory. No placeholder user text is
  allowed to clear external-input restrictions or mint consent.
- At most one existing compactor invocation, deadline at most 60 seconds (smaller
  configured wall-time limit wins), bounded summary output, existing R15i meter
  exactly once. Unsupported legacy total-token/USD caps refuse before spending;
  they are not silently ignored or reset. No live provider calls in validation.
- The printed manifest delta describes transcript-only byte/token estimates;
  system/tool request context is excluded. Do not forge a request hash for a
  request never sent. The next ordinary request still emits its actual manifest.
- One synchronous idle/busy guard covers active runs, queued/active permissions,
  questions, escalation, undo, dream, review, selection preparation and maintenance.
  Abort/shutdown join owned work. Read-only status invalidation follows actual
  maintenance segment identity, not the still-selected parent conversation.
