# H5c2c1 — scheduling metadata recovery and log preflight

Base: main 74ffbf8, PR #127, main CI 33968348026 green. Current row only.

## Contract

- Check the owned dream copy's log capacity before the only model call. Use the same header
  recovery, UTF-8 byte accounting and newline framing as append. Reserve a conservative bound
  on contradiction-count digits from the configured model-output cap; other counts are already
  known. The final bounded append still checks capacity. This is not a reservation against
  uncooperative writes, nor a guarantee that every other later failure is preflighted.
- Add SDK `resetDreamStamp` and `memory reset-dream-stamp --confirm`. Operate only on the named
  existing wiki's regular `.last-dream` file, under the canonical root mutation lock. Preserve it
  in an exclusive sibling backup without reading its potentially unreadable/unbounded content;
  then remove that directory entry to reset scheduling. Missing stamp is an idempotent no-op.
- Never initialize missing wikis, follow a stamp symlink, remove directories/special files,
  steal locks, truncate log history, or modify immutable raw records. Refuse replacement roots.
- Operators must stop running/scheduled dreams first; this maintenance command does not cancel
  them. Shared writer locks serialize short mutations, not whole provider lifetimes. Once the
  backup is created, finish the reset despite late abort; report partial failure with its backup
  path. Crash between backup creation/removal preserves both links. No power-loss guarantee.
- Workspace/manifest and swap recovery remain H5c2c2/c3. Raising explicit scan caps is still a
  valid log-capacity remedy; no automatic rotation/deletion is introduced.
- Applying a retained review copy must preserve an explicitly absent live scheduling stamp,
  not resurrect the copy's old stamp. The scheduling exception to source fingerprints permits
  this sequence, so apply must mirror both presence and absence before its first live rename.

## Validation

Real SDK and executable CLI cases: near-cap log fails with zero model calls/usage and no live
mutation; Unicode/header-repair/missing log framing; sufficient capacity preserves history;
oversized and unreadable regular stamp reset preserves bytes/mode outside wiki scans, normal
dream can run again; missing, symlink, directory, active lock, replaced root, abort and partial
unlink failures. Negative mutations must catch missing preflight/lock/type guards. Build,
typecheck, explicit Node22 suite; Claude review, exact-head three-platform PR CI, merge and
exact post-merge main CI before the next sub-row.
