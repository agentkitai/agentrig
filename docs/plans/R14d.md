# R14d — two verification lanes, explicit evaluator provenance

This completes the remaining R14d supervisor/reporting seam after R14c PR #169. E1 already
owns isolated task checks and E2 already reports separate behavior/regression/scope/human
outcomes. Reuse them, without a second evaluation engine, automatic check execution or new
live-model spend. Independent extension/provider rows may proceed in other worktrees.

## Contract

- A shared bounded supervisor `VerificationEvidence` schema carries task/run identity, an
  evaluator identifier/checker-source digest, regression and behavior observations, cited
  check references, oracle basis, completeness and explicit PASS / FAIL / BLOCKED / SKIP.
- Existing `eval/check.mjs` produces these fields around its actual pinned regression worker
  and evaluator-owned user-facing behavior assertions. Submitted tests remain a separate E1
  lane: a passing test that shares the implementation's mistake is not behavior evidence.
  Behavior success records its actual negative/adversarial probes. A4/X4 explicitly designate
  a different, existing human-semantic component: their automatic golden answer/citation checks
  do not assess prose. Only the existing manifest-owned human verdict resolves that component;
  no automatic adversarial probe is fabricated or claimed. Pending human assessment blocks.
  Human PASS cannot waive actual FAIL, partial observations, absent references, or an unknown/
  same-assumption oracle. Checker JSON claiming human approval cannot replace the manifest gate.
- Shared reduction preserves any failure over a block. Partial/missing observations or
  references, unknown or same-assumption oracle basis, and behavior without a separate
  surface/golden/second-method observation and negative probe are BLOCKED, never partial PASS.
  SKIP needs a declared pre-run exclusion without an attempted observation. Mixed pass/skip is
  BLOCKED. E2 additionally enforces its existing no-work pre-run SKIP and scope/human gates.
- E2 validates matching task/run identity and retains the new report alongside all existing
  outcome, cost and coverage data. Missing metadata on historical reports is explicitly
  unverified in text, without rewriting E3 archive bytes or changing legacy JSON outcomes.
- `GradeInput.verification` and lazy `attach(..., { verification })` accept optional trusted
  evaluator observations. The host owns the mapping to the actual session/task/workspace.
  The loader shares existing auxiliary timeout/cancellation accounting; no loader means no
  checks execute. M6 displays the two lanes and can force false on deficits, never force true
  from passing checks. Absent legacy evidence remains visibly unverified but does not introduce
  a new mandatory gate for legacy callers. Raw R14b exits and model prose never fill this seam.

## Trust and limits

Input custody is the existing E1/E2 trusted evaluator/host boundary, not a new identity registry
or security mechanism. Schema fields and hashes alone prove neither source authenticity nor
semantic independence. A caller importing arbitrary model/workspace JSON into the trusted input
violates the contract. Reports explicitly say evaluator-attested, not authenticated independence
or semantic proof. A golden/surface/second-method label without recorded observation and probe
does not suffice, and known shared-assumption evidence is discounted.

The fixed E1 checker uses its inspected oracle code; it does not derive expectations from the
agent's submitted tests. References/digests allow inspection, not automatic correctness proof.
Its child workers execute submitted JavaScript: a missing completion marker after exit zero
blocks incomplete assertions, but the marker is cooperative, not authentication against code
forging stdout or modifying its host process. Existing E1 isolation and external artifact review
requirements remain. There is no claim to solve semantic test independence or hostile-JavaScript
attestation. Models can still misjudge evidence; deterministic reduction only lowers verdicts.

New text fields are at most 512 characters, existing human-verdict fields retain their 4096
character limits, each lane has at most eight references, and there are exactly two lanes.
Invalid/oversized direct grading input is a bounded unverified block; a malformed trusted loader
result reports an auxiliary error and produces no grade, not a pass. File/process schemas reject
invalid values. E2 retains original attested fields plus the derived report for inspection.
No new event type, history rewrite, grammar, eval command,
provider call, numeric score or automatic execution is added.

## Validation and delivery

Actual E1 X2 checks run against a correct strict numeric predicate and a broken coercing one.
Both keep pinned regression and submitted same-assumption tests green; only the independent
behavior check distinguishes them. The produced JSON is stored and read through E2, then passed
by the trusted loader into actual attached M6 requests against an optimistic scripted grader.
Additional controls cover missing probe, partial and same-assumption evidence, wrong run ID,
legacy report compatibility, failure precedence, pre-run skip, no forced model pass, and actual
zero-exit incomplete worker behavior. No live provider or network evaluation calls.
