# R17e — visible supervisor and memory

Builder: **Claude/operator outside AgentRig** (no AgentRig session drove this row; the dogfood gate
R17a is recorded as unmet for it). Branch `feat/r17e-visible-guidance`, base main `4af5d21`. No
child/reviewer spawning, no E3 or live-provider spending, no permission/authority changes, no work

ROADMAP acceptance for this row: *a fixture intervention appears as a transcript line and `/why`
names it.* The row's own sentence adds the rest: each intervention and each recall renders as one
line a person can read — what it noticed, what it did, what it cost — memory recall shows the page
and the claim rather than a count, and nothing is added to the model prompt that is not also
visible.

## What was actually wrong

Everything the supervisor and memory do was already in the log, and almost none of it was legible.

- `supervisor.intervention` rendered as `⚠ inject_guidance: <message>`. It never said what had been
  noticed (the signal was a separate event), and — worse — it is recorded *before* the rung is
  applied, so a decision that was only queued, or that the harness could not perform at all, read
  exactly like one that happened.
- A successful `memory_search` rendered as `✓ memory_search retry · 12ms · ok`. The pages and the
  claims it recalled were invisible; a count is not something a reader can disagree with.
- The memory index is injected into every system prompt with no tool call behind it. It was
  measured in `context.manifest` and shown by `/context` on request, and announced nowhere.

## Contract

### Bounded independent review repair

The independent Codex review of `c14322d` found three defects: conversation insertion was
mislabelled as request delivery after a pre-model veto, companion decision indexes outlived the
64-decision cap, and post-tool replacement memory content was not shown. The operator reproduced
all three and repaired them together: explicit request-attempt evidence and terminal state,
bounded-array correlation with weak attribution ownership, and bounded sanitised replacement
text labelled as hook/core content rather than a verified memory claim.

Independent Claude also reproduced outcome bookkeeping being sent back through detectors;
`supervisor.outcome` now joins the existing self-event exclusion. Auxiliary wording now points
to the run's actual call/usage record without inventing a count of one. No change to permission,
hook, detector threshold, provider or budget defaults. Original review heads remain frozen;
fixes receive a focused delta check, not new general review rounds.

`steer` proves insertion into the conversation, not remote model receipt. `/why` explicitly
distinguishes a recorded request attempt from a vetoed/unattempted turn and marks ended turns
finished even when no `turn.end` was emitted. Post-tool patch lines show bounded model-facing
content; they do not themselves prove a subsequent provider request occurred.

### 1. A decision and its effect are two records

`supervisor.intervention` gains two optional fields: `id`, and `noticed` — the signal(s) the policy
acted on (bounded at 16; the observer records at most 8). `LadderPolicy.cause()` reports which
signal built which intervention, so `noticed` is the one signal acted on rather than the whole
batch; a custom policy that cannot attribute gets the batch, which is a weaker claim but never a
wrong one.

The new `supervisor.outcome` record says what applying it did:

| outcome | means |
|---|---|
| `queued` | text was handed to `steer`; it lands at the next turn boundary and the `steer` event is the only receipt |
| `applied` | the effect happened synchronously — a plan gate went up, an abort was requested, a human was asked |
| `no-action` | the rung ran and produced nothing to inject (an empty reviewer, a passing grade) |
| `unavailable` | this harness cannot perform the rung (no escalation handler, no reviewer, no grader, an unimplemented rung) |
| `failed` | applying it threw, timed out, or was cancelled |

`cost` carries only claims the harness can stand behind: `modelCalls: "none"` for the heuristic
rungs (local computation — nothing to bill), `"auxiliary"` plus the `auxiliaryId` of the
`auxiliary.usage` record for the LLM-backed ones, and `injected: { bytes, hash }` for text queued
for the prompt. Auxiliary usage is **pointed at, never copied**: an unfinished snapshot means total
consumption is unknown, and summing it here would manufacture a number. Injected bytes are prompt
size with the manifest's ~4-bytes-per-token estimate, explicitly *not* billed tokens.

Both are `SupervisorRecord` variants, so the observer's existing narrow write gate still applies:
nothing new became tool-emittable, and `TOOL_EMITTABLE_EVENTS` is untouched.

### 2. `/why` explains what was injected, not what was proposed

`GuidanceLog` (core) folds the event stream into the last turn's explanation. Its rules:

- **Attribution.** Core drains queued steers and pushes them onto `messages` immediately before
  `turn.start` (agent.ts). Guidance therefore belongs to the turn whose `turn.start` follows it,
  never to the turn it was decided during. A steer recorded after the last `turn.start` is reported
  as queued for a turn that has not started.
- **Delivery.** A `steer` event proves conversation insertion; a later `model.request` proves only
  a request attempt, not remote receipt. Without it `/why` explicitly reports no recorded request.
  A steer still queued when the session ends
  is recorded by core as a non-delivery `error` (through the shared `undeliveredSteerMessage`) and
  is reported under "never delivered", never under injected.
- **Which decision.** A supervisor steer is matched to the outcome whose `cost.injected.hash` is the
  digest of that exact text, in queue order. Only a steer with `source: "supervisor"` may claim one,
  so a user message with identical text cannot wear the supervisor's reasoning.
- **Prompt context.** The automatic blocks and the memory tool results come from that turn's
  `context.manifest`, which is measured from the prepared outgoing request — not a re-read.
  `/why` quotes the injected memory index only when the text the CLI holds hashes to the block the
  manifest recorded; otherwise it says the content is not held by this view and gives the hash.
- **Lifecycle.** The fold resets on `session.start`, `session.resume` and `session.fork`, and the
  TUI drops it at `/new` and `/clear`. A new, resumed or forked conversation cannot show the
  previous run's turn as current.

`/why` is local inspection: a fold over events this process already received. No provider call, no
file read, no configuration load, and it answers after the last turn has ended as well as during.

### 3. Recall shows the page and the claim

`memory/recall.ts` owns both halves of the retrieval display: `formatRecallHits` writes it and
`recallEvidence` reads it back, with a round-trip test. A backend's returned text is flattened to
one line there, so text a backend returns cannot forge a second `page [index]` entry in the tool's
own output. The CLI pairs a memory `tool.call` with its `tool.result` and renders page + claim,
bounded and sanitised, disclosing pages omitted by the display bound and results the tool itself cut
short. A failed, denied or unmatched call renders **nothing** — the existing failure line already
says what happened, and "memory says …" built from an error is the exact false claim this row exists
to prevent.

The injected index announces itself once per session (and again if it changes) from the manifest:
`✻ memory in the prompt: index injected — N B, ~M est. tokens … (no tool call; /why shows it)`.

Both surfaces get all of this: the TUI transcript and headless `run`.

## Limits

- An outcome recorded after `session.end` is dropped by core, because `session.end` must stay the
  log's last line. A terminal rung (`abort`) can therefore lose its outcome line; the session's own
  end reason remains the receipt for it.
- `noticed` and the digest match are the observer's own account of its reasoning. They make the
  decision auditable, not correct: a detector can still misfire, and the ladder's guidance is
  advisory text, not evidence.
- Prompt bytes and `~est. tokens` are byte counts and the manifest's fixed estimate. They are not
  the provider's tokenisation and never a bill.
- A recall line is what the retrieval tool returned. A `post_tool` hook that rewrites what the model
  saw is a separate `tool.result.patched` event with its own line; the recall line does not restate
  the patched text.
- `/why` explains the *last* turn. Earlier turns' guidance is in the log and in `sessions show`.
- Pre-R17e logs have no `id`, `noticed` or outcome. Every surface degrades to the older rendering
  and says the notice was not recorded, rather than inventing one.
- The dogfood gate (R17a) is unmet for this row: it was built by Claude/operator outside AgentRig.
