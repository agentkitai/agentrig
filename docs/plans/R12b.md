# R12b — Semantic approval prompts and scoped confirmation

## Contract

The TUI explains the registered permission class, declared paths, cwd, and trusted post-hook
literal shell operation. It does not infer effects from tool names, model prose or MCP hints.
Write-class paths may change; exec may mutate files and reach the network. Read-class metadata
is not proof of read-only behavior or no network. Network-class requests do not identify all
destinations. Missing paths mean unknown effects, not an empty effect set. Arbitrary registered
host code remains trusted; this is an authorization UI, not a program-analysis engine or sandbox.

Details are printed when the corresponding queued prompt becomes active. Dynamic values are
JSON-escaped. Declared-path summaries cap at 128 entries / 16 KiB with explicit omission markers;
scope checks still require every declared path. The live editor uses the existing viewport.

Existing `y`/`a`/`n`/`d` remain allow-once / standing allow / deny-once / standing deny.
The prompt explicitly describes standing authority as any resource/class/cwd for this exact tool
in the live session, including the currently shared child group, subject to explicit base rules.

`s` edits one bounded JSON scope:

- Declared non-shell paths: `{ "pathPrefix": "/absolute/prefix" }`. Requires 1–128 nonempty
  declared paths, all lexically inside the prefix. The current cwd is also fixed in the grant.
- Supported foreground shell: `{ "commandPrefix": ["git", "status"], "cwd": "/absolute/cwd" }`.
  The prefix is literal argv, not shell syntax/globs. It must cover the current parsed command;
  additional trailing arguments are permitted in future. Unsupported/background shell requests
  cannot fall back to an unrelated declared-path scope. Initial argv is the full current argv.

Input is capped at 24 KiB, with strict key/type validation and existing R12a/R12e limits. Relative
paths, unknown keys, malformed/oversized inputs and scopes missing any current path/argv/cwd are
refused. No default widening or partial installation occurs. Empty argv elements cannot be
prefix words under the existing R12e schema; users may deliberately edit a shorter valid prefix.

Enter validates and prints the exact future grant **without installing it**. A separate `y`
confirms; `e` edits and invalidates preview; `n`/escape cancels scope mode without deciding the
request. Editing also invalidates preview. Installation revalidates the proposal and registry
revision, then uses the same live R12a registry/audit pipeline. Session-only grants preserve
current child sharing (`delegable: true`); explicit child filtering remains R12d. Path scopes are
lexical/advisory, not symlink containment. Argv scopes do not attest executable identity, PATH,
Git hooks/configuration, effects or network destinations.

Both ordinary Ink-key handling and ordinary bytes adjacent to protocol markers use the same
scope action path. Bracketed paste cannot answer a permission or alter a scope. A single raw
chunk cannot both produce a preview and confirm it with trailing `y`. The same existing input
quiet point coalesces redraws. Separate sandbox-escalation and MCP-definition-change consent
never enters scope mode or creates standing grants; their exact existing consent checks remain.

## Implementation boundary

Core exports the pure `permissionGrantCoversRequest` matcher used by both registry dispatch
and CLI proposal validation. It only checks operation/resource/constraints, not live
subject/duration or installation; callers validate records and use the registry for authority.
No temporary preview grant, permission event schema change, new provider call, or persisted
authority is introduced. R12c richer grant lists/hit counts/why-lines and R12d inheritance stay
separate. Explicit base allows/denies, MCP pinning and sandbox composition are unchanged.

## Verification

Unit/controller checks discriminate all-path scope, argv/cwd mismatch, malformed bounds,
separate consent, reset/preview invalidation and unknown effects. Real Ink input drives the
actual CLI builder, registry, session store and inert shell: both input paths confirm a narrow
grant, execute compatible commands and refuse an unsupported compound command. Real file writes
prove a mismatched scope does not dispatch the current request, and a confirmed prefix permits
two in-scope writes but refuses an outside write. Exact future scope is observed on stdout before
confirmation, and `permission.granted` precedes `tool.call` in the persisted log.

Build/typecheck/full tests, named restored mutations, one bounded independent Claude review,
current-main integration and exact-head three-platform CI gate delivery. Receipts belong in
the PR and STATUS; optional polish goes only at ROADMAP's end.
