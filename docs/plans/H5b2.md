# H5b2 — bounded ingest and auxiliary accounting

Starts from updated main 5fc2cb8 after PR #123 and green main CI 33958820304. This is the
second half of H5b; dream lifecycle adoption remains H5c and reviewer/grader/session-event
integration remains H5d.

## Contract

`ingestSession` owns a `MaintenanceRun` and forwards its signal through the same-session lock,
model/backend calls, bounded file reads, reservations, checked page updates, index/log writes,
pin rechecks and provenance. External calls race the linked abort/deadline; late output or usage
cannot reach subsequent ingest commits or mutate an already-delivered report. Cooperative work
receives abort. Call cleanup never waits indefinitely for an iterator's `return()`.

Local writes are **not** raced away: the owner retains its lock through in-flight filesystem work
and cleanup. Abort is checked before committing a new atomic rename. A rename/O_EXCL creation
already submitted to the OS can finish after the abort signal; this is not rollback. A newly
created reservation finishes its index bookkeeping, matching H5a's committed-write rule. Later
mutations stop. Reports say `not-started`, `may-be-partial`, or `completed` for local writes.
Partial captures retain H5b1's pending/retry behavior. Optional backend delivery happens after
local completion; abort cannot undo accepted remote requests and retry does not replay a completed
capture merely to repair backend delivery. There is no exactly-once remote-delivery claim.

Bounds are finite, validated, and adjustable through SDK `limits`:

| Bound | Default |
|---|---:|
| Total run / individual external call | 5 minutes / 30 seconds |
| External calls / coverage spans | 66 / 64 |
| Model input / output UTF-16 characters per call | 32,768 / 65,536 |
| Model events per call | 4,096 |
| Raw file / individual wiki file | 8 MiB / 8 MiB |
| Raw events / distilled facts / target pages including source | 20,000 / 1,024 / 256 |
| Supplied attempts | 128, also within model-input characters |
| Lore response body | 2 MiB |

`maxSpanChars` (default 6,000) and requested `maxTokens` (default 2,048) remain existing SDK
options. Planning stops at the span cap, before constructing an unbounded list. Excess input or
coverage fails visibly instead of being silently truncated and marked complete. Reads require
regular files and cap bytes even if a file grows after stat; nonblocking opens avoid hanging on
FIFOs. Existing huge memory files fail bounded maintenance instead of being rewritten partially.

These bounds constrain harness work, not arbitrary code supplied as a provider/store/backend.
Synchronous event-loop-blocking plugin code cannot be preempted in-process. An uncooperative
remote request may continue after abandonment; its final cost is unknown. OS filesystem operations
can also exceed a requested wall deadline; the harness waits for safe ownership cleanup rather
than returning while a detached writer still owns a lock. No worker-process hard-kill boundary or
hard monetary budget is claimed. No paid live-provider evaluation is required for these tests.

## Accounting

Core exports only the shared `AuxiliaryCall`/`AuxiliaryReport` types; memory still imports core
types only. Each logical auxiliary call records provider/model, duration, outcome, last reported
usage snapshot and whether its total usage is known. Multiple cumulative usage events replace,
not sum, one call's snapshot. Totals keep normal input, output, cache reads and cache writes
separate. Missing usage, synthesized/partial adapter counts, failed/abandoned calls, backend
calls and provider retries with unreported overhead remain explicitly unknown. Partial reported
counts are retained. Adapter fallback zero events now carry additive `reported: false`.

Ingest returns the report and delivers an isolated copy through `onUsage` on success or failure
of a valid run. Reporter failure cannot replace the operation's outcome. Preflight invalid limits
reject before creating a run/provider call. Zero-call work reports zero auxiliary cost; any actual
external calls have `costUsd: null` until pricing/remote costs are known, never an invented $0.
The CLI and scheduled ingest display the separate auxiliary summary, including failure paths.
This does not yet add durable session events or combine main/auxiliary session totals (H5d).
The legacy dream `completeJson` path is deliberately not claimed bounded until H5c migrates it.

## Validation

Deterministic fixtures cover cooperative and ignored abort, never-settling calls, late output and
usage, cleanup without awaiting a stuck iterator, call/run deadlines, input/output/event/span/
fact/page/file limits, reservation and pending-capture interruption/retry, preserved chronology,
backend timeout and late provenance, actual Lore fetch signals/body limits, usage snapshots,
cache counts, absent/partial/synthetic usage, retry overhead and zero-call accounting.
Existing H5a/H5b1 cross-process and corruption tests remain required. Windows CI includes the new
lifecycle suite; Linux/macOS run the full suite. Review and exact-head CI are gates before merge.
