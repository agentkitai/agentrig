## Contract before implementation

- One `ask_user` builtin, bound by actual factory identity to the core runtime.
  A question has a nonblank prompt (2048 characters), two to four distinct options
  (256 characters each), and always permits free text (4096 characters).
  Runtime question IDs correlate protected `question.asked` / `question.answered`
  events with the actual session and tool call; tools cannot forge those events.
- The trusted SDK `onQuestion` handler is separate from permission approval and
  supervisor escalation. A 120-second question deadline, session cancellation,
  unsupported client, invalid answer or unavailable answer policy settle once.
  An unavailable required answer fails the run before another model call; abort
  remains abort. Later queued calls do not execute after a failed question.
- Human answers and explicitly automated first-option/file/supervisor answers have
  distinct provenance. Automated answers are external advisory content. Even a
  human clarification is not a permission grant or blanket fresh-user reset.
  Normal hooks, tool permissions, sandboxing, history and export still apply.
  No automatic supervisor model answerer is introduced; a trusted host may supply
  one only through an explicit handler and label its answer as supervisor-sourced.
- TUI questions use a separate FIFO of at most eight pending entries, exact-entry
  settlement and late-answer rejection. Input priority is permission, question,
  then supervisor escalation. Abort, shutdown and session end settle owned entries.
  Options and free text are rendered within the existing bounded viewport.
- Headless `run --answer-policy` accepts `fail` (default), `first-option`, or
  `file:<path>`. The file is a bounded regular non-symlink JSON file (64 KiB,
  at most 16 exact prompt/options matches); no scripts, expansion or fuzzy match.
  It supplies literal answers, never fresh human authority. Heartbeat suppresses
  the question tool, preserving empty/no-action execution contracts.
- ACP clients explicitly negotiate version 1 questions in initialization metadata.
  `_agentrig/question` is a separate bounded outbound request, never permission
  options. Unsupported clients fail closed. Shared pre-SDK byte reservations stay
  held until a real reply or transport close even after local cancellation; the
  existing combined eight-outbound-request limit remains. No new transport.
- Actual fake-provider CLI/TUI/ACP controls must show question, answer and resumed
  model request; default headless refusal is nonzero with no next model call.
  Cover queue/cancel/deadline/late reply, event forgery, grants, external expansion,
  history, automated provenance and heartbeat. Named removed-guard mutants must
  fail and be restored. Full build/typecheck/container-enabled tests, one Claude
  review with material findings fixed, and exact-head/post-main four-check gates.

## Limits

Answers may contain sensitive text and are intentionally recorded in the raw log.
Provenance is a runtime attribution, not proof that model-generated options are
safe or that a human understood them. Trusted SDK callbacks are cooperative host
code; cancellation cannot guarantee remote work or hostile JavaScript has stopped.
The question is clarification only: execution still needs normal authorization.

- AcpQuestionLocalCancellationRemoved: actual unanswered settlement hung until the
  five-second test deadline. With the guard, the prompt finishes while its SDK
  reply reservation remains held until a late reply/close.
