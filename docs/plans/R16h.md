## Implementation evidence

Config resolution reaches actual startup and real Ink in both ordinary and
protocol-adjacent input. Startup captures a validated copy before asynchronous
construction; mutating the caller's configuration afterward does not change the
effective answer key. Invalid direct settings refuse before provider construction
or mounting. Existing whole-object config precedence is retained.

Removing only the startup `settings` prop caused both retained integration cases
to fail (1046/1018ms): prompts showed default y, not configured j. Restoring the
wiring passes all five startup controls. Build/typecheck pass; the initial
settings/config/startup group passed66 tests. Initial test failures were fixture
setup mistakes (user state nested inside the project and omitted budget defaults),
corrected without changing trust or budget enforcement. Final counts follow.

Controller prose no longer hard-codes default permission keys; the live prompt
names the effective keys. ASCII-only key matching also excludes Unicode casefold
lookalikes. NO_COLOR tests must start a fresh process with FORCE_COLOR set before
Ink/Chalk imports; changing it after imports is not positive colour evidence.
